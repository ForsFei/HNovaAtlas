## 一个先有鸡还是先有蛋的问题

学完前面几篇你可能已经隐约察觉到一个悖论：

- 程序存在硬盘里，CPU 从内存取指令执行
- 但开机那一刻，**内存是空的**（断电即忘）
- CPU 手里没有任何程序，它怎么知道该干什么？

CPU 通电瞬间确实"失忆"了。解法是：给它安排一段**永远不会丢失的启蒙程序**，藏在主板上的一小块特殊芯片里——这就是开机接力的第一棒。

一句话总结这场接力：**固件点火 → 引导程序传棒 → 操作系统接管**。每一棒都只做一件事：把更大、更完整的下一棒装进内存。

## BIOS 与 UEFI

主板上那块"启蒙芯片"里的固件，老一代叫 BIOS，现代电脑几乎都是它的继任者 UEFI：

| | BIOS（_legacy_） | UEFI（现代） |
|---|---|---|
| 外观 | 蓝底白字，键盘操作 | 图形界面，可支持鼠标 |
| 启动速度 | 慢，逐项自检 | 快，可并行初始化 |
| 硬盘支持 | 较旧规则（MBR，最大 2 TB） | 新规则（GPT，超大硬盘） |
| 安全 | 无 | Secure Boot 防止引导被篡改 |

装系统、设启动顺序、开虚拟化功能时进的那个界面，就是它们。

<Callout type="info" title="为什么重启能修复很多问题？">

重启 = 清空内存（工作台）→ 从硬盘重新加载一套全新的操作系统。那些"运行久了状态混乱"的程序和内存碎片全部归零，而硬盘上的数据完好。这就是"重启大法好"的原理：**代价最小的整体归位**。

</Callout>

## 睡眠、休眠与关机

理解了内存的易失性，三种关机方式就一目了然：

- **关机**：断电，内存清空，下次完整走一遍开机接力
- **睡眠**：内存**持续供电**保持现场，恢复秒回；代价是睡眠中也耗一点电
- **休眠**：把内存**完整抄写**到硬盘后彻底断电，开机时再抄回来；恢复比睡眠慢，但不耗电

## 动手试一试

1. 重启你的电脑，进入 BIOS/UEFI 界面（开机时按 F2/Del 等），看一眼启动顺序设置，不做修改退出。
2. 观察一次开机：从按下电源到登录界面大约几秒？其中固件自检占了多少？（品牌 logo 画面就是固件阶段）
3. 对比一次"睡眠唤醒"和一次"关机再开"的时间差，用接力赛模型解释差距。
