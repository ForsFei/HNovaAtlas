## 一个找书的例子

同样一千本书，两种放法：

- **地摊式**：全堆在一张桌子上。找某本书？只能一本本翻，最倒霉翻一千本。
- **图书馆式**：按编号分架排好。找 37 号书？直奔 37 号架，一步到位。

书的总量没变，**放法**变了，找书速度天差地别。数据结构研究的就是这件事：**数据在计算机里怎么摆，才能让常用的操作最快**。

## 摆法决定什么

没有"最好的摆法"，只有"对某个操作最好的摆法"：

| 你的需求 | 合适的摆法 |
|----------|-----------|
| 经常按位置取第几个 | 排好队（数组） |
| 经常按名字找信息 | 配索引（哈希表） |
| 经常处理"最新来的" | 叠盘子（栈） |
| 经常处理"最早来的" | 排队叫号（队列） |
| 数据之间有层级 | 文件夹树（树） |
| 数据之间是多对多关系 | 关系网（图） |

后面几篇就是把这些摆法一个个拆开讲。

## 数步数：衡量快慢的尺子

比较快慢不能靠感觉（不同电脑速度不同），要**数操作步数**，而且关心"数据变多时步数怎么涨"：

| 步数走势 | 学名 | 直觉 | 例子 |
|----------|------|------|------|
| 数据翻倍，步数不变 | O(1) | 恒定 | 按编号取书 |
| 数据翻倍，步数跟着翻倍 | O(n) | 翻一遍 | 地摊找书 |
| 数据翻倍，步数只多一点点 | O(log n) | 折半折半 | 二分猜数字 |
| 数据翻倍，步数翻四倍 | O(n²) | 两两配对 | 全班两两握手 |

<Callout type="tip" title="记学名不如记走势">

O(1)、O(n) 这些记号先当"绰号"看，重点是走势：**数据量变大 10 倍、100 倍时，你的程序是慢 10 倍还是慢 10000 倍**。小数据怎么写都快；数据一大，摆法的高下立刻见生死。

</Callout>

## 数步数实战：两种找法

在无序的一千个数里找目标 42：

```python filename="find.py"
numbers = list(range(1000))
import random
random.shuffle(numbers)      # 打乱，模拟无序

# 摆法一：挨个找 —— 数据多大，最坏就找多少步
for n in numbers:
    if n == 42:
        break

# 摆法二：如果排好序，可以折半找 —— 千个数只要约 10 步
ordered = list(range(1000))
low, high = 0, len(ordered) - 1
steps = 0
while low <= high:
    steps += 1
    mid = (low + high) // 2
    if ordered[mid] == 42:
        break
    elif ordered[mid] < 42:
        low = mid + 1
    else:
        high = mid - 1
print(steps)      # 9 步
```

同样找 42：挨个找最坏 **1000 步**，折半找只要 **9 步**。数据涨到一百万个呢？100 万步 vs 20 步。**这就是数据结构（含排序、树）存在的意义**。

<Callout type="info" title="折半为什么这么猛">

每次折半，剩余范围除以 2。1000 → 500 → 250 → 125 → 62 → 31 → 15 → 7 → 3 → 1，十步内必然见底。反过来算：2 的 10 次方 = 1024，所以一千个数只要 10 步。第 5 篇讲的"树"，就是把这个折半思想变成一种正式的数据摆法。

</Callout>
