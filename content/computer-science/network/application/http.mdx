## 一问一答的对话

前面几篇解决了"怎么把字节送到对方电脑"。但浏览器和网站服务器之间说什么"台词"？这就是**应用层**的事。HTTP 是 Web 世界的普通话：**浏览器问一句，服务器答一句**，永远一问一答。

```
浏览器 → 服务器：我要 /index.html（GET 请求）
服务器 → 浏览器：好的，给你（200，HTML 内容）
浏览器 → 服务器：再给我 logo.png（GET 请求）
服务器 → 浏览器：好的（200，图片）
...几十轮来回，页面拼装完成
```

## 请求：问题怎么问

用命令行就能亲眼看到一次原始对话：

```bash filename="命令行"
curl -i https://example.com
```

```text filename="响应（节选）"
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

<!doctype html>
<html>...
```

浏览器发出的请求由三部分组成：

```text
GET /index.html HTTP/1.1          ← 请求行：方法 + 路径 + 协议版本
Host: example.com                 ← 请求头：元信息（身份、偏好……）
（空行）
（请求体：GET 通常没有；提交表单时才有）
```

## 方法：问句的类型

HTTP 请求行开头的方法，表达"我想干什么"：

| 方法 | 含义 | 例子 |
|------|------|------|
| GET | 我要看 | 打开网页、查商品 |
| POST | 我要提交 | 登录、下单、发表评论 |
| PUT | 我要整体替换 | 更新用户资料 |
| DELETE | 我要删除 | 删掉一条记录 |
| HEAD | 只要回应头不要内容 | 检查资源是否存在 |

日常浏览 90% 是 GET 和 POST。

<Callout type="tip" title="GET 与 POST 的直观区别">

GET 是"去看"，参数拼在网址里（`?page=2`），能收藏能分享；POST 是"去做"，参数藏在请求体里——密码、支付这类动作必须是 POST，既不暴露在网址里，也不会被浏览器随手重新发起。

</Callout>

## 状态码：回答的开头三个数字

服务器每个响应都以三位数字开头，一眼判断结果：

| 状态码 | 含义 | 你见过的场景 |
|--------|------|--------------|
| 200 | 成功 | 正常打开网页 |
| 301 / 302 | 搬家了，去新地址 | 旧链接自动跳转 |
| 304 | 没变化，用你本地缓存的 | 刷新页面时静态资源秒开 |
| 404 | 你要的东西不存在 | 打错的网址 |
| 403 | 有，但不给你看 | 无权限的页面 |
| 500 | 服务器自己出错了 | "服务器繁忙" |

规律：**2 开头成功、3 开头跳转/缓存、4 开头你这边的问题、5 开头服务器的问题**。看懂第一位数字，排查"网页打不开"就知道该怪谁了。

<Callout type="info" title="404 为什么这么有名">

404 是少数被设计成趣味页面的错误码——很多网站把它做成彩蛋。它精确的含义是：服务器活着，但"你找的资源不存在"。和 500（服务器自己坏了）有着本质区别。

</Callout>

## 无状态：服务器不记得你

HTTP 天生**无状态**：每个请求都是全新的对话，服务器处理完就忘。你刷新页面，服务器并不"记得"你刚来过。

那登录状态怎么保持？靠**Cookie**：登录后服务器发给你一张"通行证"（存在浏览器里），之后每个请求自动出示它，服务器凭通行证认出你。Cookie 之于 HTTP，就像会员卡之于一家不记脸的商店。

## 动手试一试

1. 用 `curl -i https://example.com` 看一次原始响应，找到状态码和 Content-Type。
2. 打开浏览器开发者工具（F12）的 Network 标签，刷新任意网页，数一数这次页面发了多少个请求。
3. 思考：为什么"刷新页面"第二次总比第一次快？（提示：304 与缓存）
