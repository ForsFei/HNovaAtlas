## 一切从"传文件"开始

两台电脑面对面，怎么把一个文件传给对方？拉根网线，按约定好的规则发字节流——这就够了。三台、十台呢？两两拉线，线会疯长。聪明的做法：**所有电脑接到一个公共的"转接设备"上**，谁要发给谁，通过转接设备送达。

把"转接设备"再连"转接设备"，网络越连越大——今天连接全球几十亿设备的互联网，本质就是这句话的放大版：**网线 + 交换规则的组合**。

## 邮政系统：网络的第一类比

计算机网络的几乎所有概念，邮政系统里都有对应：

| 邮政 | 网络 |
|------|------|
| 信封上的收件地址 | IP 地址 |
| 邮局分拣中心 | 路由器 |
| 一封信 | 一个数据包 |
| 地址写错退回 | 找不到目标报错 |
| 邮政编码规则 | 网络协议 |

**协议（protocol）**这个词贯穿全系列：它就是"双方事先约定好的格式和规矩"。发信人、邮局、收信人都按同一套规矩写地址、分拣、签收，信才能送达——网上所有设备同理。

## 分组交换：把大象切成快递

一个 1 GB 的电影，能装进"一封信"寄走吗？不能——**要切成几百万个小包裹**，这就是分组交换（packet switching）：

1. 发送端把数据切成一个个**数据包**（packet），每个包几千字节
2. 每个包都带着目标地址，**独立**在网络中旅行
3. 路由器像分拣中心：看一眼地址，决定交给下一站谁
4. 到达接收端，按序号重新拼装成完整文件

<Callout type="info" title="为什么切块比整块寄好？">

如果整块独占线路，你传电影时别人只能干等，且中途出错要全盘重来。切块后：**大家共享线路**（你的包裹和别人的包裹交错流动）、**坏一个补一个**（不用重传整部电影）、**路线灵活**（这条路堵了走另一条）。互联网的健壮与高效，根源就是"切小块、带地址、独立走"。

</Callout>

## 路由器：不认识你，只认识方向

包裹怎么跨越成千上万公里到达你家？没有任何一台机器掌握全网地图。每个路由器只回答一个局部问题：**"去这个方向，我该把包裹交给哪个邻居？"**

```mermaid
flowchart LR
  A["你的电脑"] --> R1["家庭路由器"]
  R1 --> R2["小区出口"]
  R2 --> R3["运营商骨干"]
  R3 --> R4["数据中心路由器"]
  R4 --> B["网站服务器"]
```

像寄一封跨国信：你不需要知道全程路线，只把它交给邮筒；每个分拣中心只负责"往正确的大方向递"。一跳一跳接力，直到送达。这个"逐跳转发"的设计，让互联网可以无限生长——每台路由器只需认识自己的邻居。

## 两条网线之外

真实的"网线"多种多样：家里的 Wi-Fi（无线电波）、光纤（光信号）、4G/5G（无线基站）。物理介质可以随便换，**上层协议不变**——就像信可以走飞机也可以走轮船，邮政规则不变。这种"分层"思想是下一篇的核心。

## 动手试一试

1. 在命令行运行 `ping www.baidu.com`，观察数据包往返时间——你刚刚亲手发了几十个"包裹"。
2. `tracert www.baidu.com`（Windows）可以看到包裹途经的每一站路由器——逐跳转发的实景。
3. 思考：为什么视频通话卡顿时画面是"花屏小块"而不是整段卡死？（局部丢包只影响局部画面块）
