## 硬盘的真相：只有编号的格子

计组篇说过，硬盘是一大片能存 0 和 1 的介质。但它的物理形态既没有"文件"也没有"文件夹"——只有**一块块编号的扇区**（类似"第 38291 号格子起存了这些字节"）。

把一堆裸格子变成你熟悉的"`照片/旅行/IMG_0001.jpg`"，靠的就是**文件系统**——硬盘的图书馆管理系统。

## 文件系统做三件事

1. **切分**：把硬盘切成统一大小的**块**（通常 4 KB，和内存页呼应）
2. **编目**：每个文件记录"我占了哪些块"（索引卡）
3. **命名**：用**目录**（文件夹）把索引卡组织成树

你双击打开一个文件，文件系统的幕后动作：

```text
1. 沿目录树逐层查找：C盘 → 用户 → 照片 → 旅行
2. 找到文件的索引卡：内容分布在第 500-503、510 号块
3. 把这些块读出，拼装成完整文件交给你
```

## "删除"的真相：只是撕掉索引卡

一个反直觉的事实：**删除文件时，内容并没有被擦掉**。文件系统只是把索引卡标记为"空闲"，宣布"这些块可以再利用"。

- 原数据还躺在那些块里，直到被新文件覆盖
- 这就是**数据恢复软件**能找回文件的原因（趁块还没被覆盖）
- 这也是为什么"彻底删除"要反复覆写，或对硬盘整盘加密

<Callout type="info" title="回收站是文件系统之上的礼貌层">

删除先进回收站 = 索引卡换到"待定区"而不是销毁，给你一次后悔机会。清空回收站才真正撕卡。有些工具"Shift + Delete"直接撕卡，所以更要小心。

</Callout>

## 文件 vs 文件夹 vs 一切皆文件

文件夹不存内容，只存"这个目录里有哪些条目"——本质是一张子索引卡。树形结构（数据结构篇的树！）让任何文件都有唯一路径。

Linux 世界还有个著名设计：**一切皆文件**。硬盘是文件（`/dev/sda`）、键盘是文件、网络连接也能当文件读——统一成"读写文件"一种操作，工具和思维都省了。

## 动手看一眼：碎片与空间

两个常见现象，现在都能解释：

- **文件碎片**：文件太大时连续的空闲块不够，只好东一块西一块存放——机械硬盘来回寻道变慢，SSD 无感。所以"碎片整理"只对机械硬盘有意义
- **"删了文件空间没变多"**：可能有进程还握着这个文件的句柄没关（计组 io-bus 篇的"占用"），或它躺在回收站里索引卡还没撕

Python 验证文件系统行为：

```python filename="sparse.py"
from pathlib import Path

file = Path("demo.txt")
file.write_text("hello")        # 写入 -> 分配块
print(file.stat().st_size)      # 5 字节
file.unlink()                   # 删除 -> 撕掉索引卡
print(file.exists())            # False，但磁盘上的 5 个字节仍在原地
```

1. 在资源管理器查看任一文件的"属性"：大小与"占用空间"常常不同——文件不足 4 KB 也占一个完整块（想想为什么）。
2. 新建一个 txt 输入一个字，属性显示大小 1 字节左右、占用空间 4 KB，验证"按块分配"。
3. 思考：为什么下载到 99% 的文件可以直接断点续传？（提示：文件系统允许"先占块、后填内容"，已下载的块都在了）
