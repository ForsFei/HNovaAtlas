## 进程：一座独立围墙的车间

**进程**就是"正在运行的程序"，但重点不在"程序"而在**运行**——程序是硬盘上静止的文件，进程是活着的实例。同一个浏览器开两个窗口，就是一个程序、两个进程。

进程的关键特征：**每个进程有独立的内存空间**。像一座带围墙的车间：

- 自己的代码、数据、变量都在墙内
- 别的进程**无法直接访问**（隔离）
- 一个进程崩溃，围墙不倒的其他进程安然无恙——这就是为什么浏览器一个标签崩了，整个浏览器（或系统）还能活着

<Callout type="tip" title="隔离是安全与稳定的基石">

计组篇说过内核握着硬件总开关。进程隔离是另一面墙：程序 A 想读程序 B 内存里的密码？系统调用一查，越界，拒绝。**没有隔离，一个流氓程序就能毁掉整台机器**。

</Callout>

## 线程：车间里的工人

一座车间（进程）里常常需要**同时**干几件活：浏览器一边下载文件、一边渲染页面、一边响应点击。在每个进程内部再分工——**线程**：

- 进程 = 车间：拥有资源（内存、打开的文件）
- 线程 = 工人：真正干活的执行单位，**共享**车间的资源
- 每个进程至少有一个线程（主线程），可以开多个

```text
浏览器进程
├── 线程1：渲染页面
├── 线程2：下载文件
└── 线程3：响应点击
```

工人共享车间的工具柜——线程共享进程的内存，所以线程之间通信方便（直接读写共享变量），但也**容易互相踩脚**（数据竞争），这是并发编程的核心难题。

## 进程 vs 线程：分与合

| | 进程 | 线程 |
|---|------|------|
| 内存 | 独立空间，互不可见 | 共享所属进程的内存 |
| 崩溃影响 | 一座车间塌了，别家没事 | 一个工人出错可能带崩整个车间 |
| 通信成本 | 高（要走系统调用） | 低（直接共享变量） |
| 创建开销 | 大 | 小 |

Python 里两者都有现成模块：

```python filename="process-thread.py"
import multiprocessing, threading

def work(name):
    print(f"{name} 干活中")

p = multiprocessing.Process(target=work, args=("子进程",))   # 新车间
t = threading.Thread(target=work, args=("新工人",))          # 同车间的工人
p.start(); t.start()
```
