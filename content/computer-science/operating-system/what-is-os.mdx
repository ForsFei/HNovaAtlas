## 开机接力的最后一棒

计组篇讲过开机接力：固件点火，引导程序传棒，最后**操作系统内核**被装进内存、接管一切。这篇就来认识这位接管者。

操作系统的位置很微妙——它在**硬件之上、所有软件之下**：

```text
┌─────────────────────────────┐
│  你的程序：浏览器、微信、游戏  │
├─────────────────────────────┤
│  操作系统内核：大管家          │
├─────────────────────────────┤
│  硬件：CPU、内存、硬盘、网卡   │
└─────────────────────────────┘
```

一个酒店里，客人（程序）不直接操作水电、清洁、库房——所有需求都交给**管家**。操作系统就是计算机的管家：程序想要内存、想读文件、想发包，都通过管家。

## 管家的四大职责

| 职责 | 干什么 | 对应篇目 |
|------|--------|----------|
| 进程管理 | 决定哪个程序什么时候用 CPU | 多任务篇已埋伏笔，本系列第二篇 |
| 内存管理 | 给每个程序分配"工作台"，还要防串门 | 虚拟内存篇 |
| 文件管理 | 把硬盘变成文件和文件夹 | 文件系统篇 |
| 设备管理 | 统一调度键盘、屏幕、网卡等外设 | 计组总线篇打过照面 |

计组篇说的"时间片轮转"，正是进程管理的核心机制。

## 内核：管家的核心

操作系统的核心部分叫**内核**（kernel）——Windows 的内核、Linux 的内核、macOS 的内核各不相同，但职责类似。我们平时说的"Windows""Linux"，严格说是"内核 + 一整套配套软件"的组合。

<Callout type="info" title="同一个内核，无数张脸">

Android 手机和 Ubuntu 服务器跑的是同一个 Linux 内核，外观却天差地别——因为内核外面的"配套软件"不同。理解了"内核只是管家团队"，你就明白为什么 Linux 能同时统治服务器、手机和路由器。

</Callout>

## 系统调用：找管家办事的唯一窗口

程序不能自己上硬盘拿数据、不能自己划内存——**所有硬件操作必须委托管家**。程序向内核提需求的标准接口叫**系统调用**（system call）：

```python filename="syscall-idea.py"
# 你写的 Python 代码
with open("note.txt") as f:
    content = f.read()
```

这短短两行背后是一串系统调用接力：Python 运行时 → 操作系统的文件接口 → 内核核对权限 → 内核命令硬盘读数据 → 数据经内存交还程序。**你写一行代码，管家替你跑了全套流程**。

常见的系统调用就几十个：读写文件、创建进程、申请内存、收发网络数据——操作系统的能力清单，其实就是这张系统调用表。

<Callout type="warning" title="权限：管家为什么值得信任">

内核运行在特权模式，普通程序运行在受限模式——程序物理上**没有能力**绕过管家直接碰硬件。这就是为什么病毒不能随手删你文件（需要权限）、为什么每个程序之间互相隔离。管家手里握着硬件的总开关。

</Callout>
