## 这一节先固定范围

前面学习 S7 和 OPC UA，这里进入三菱设备常见的 MC 通信。本轮只实现 **TCP、3E 帧、Binary、Q/L 设备指定格式、直达本站 CPU** 的基础批量字/位读写；不把“品牌相同”当作所有 CPU、模块、帧和命令都兼容的证据。

配套服务端是仓库自己实现的小型回环数据区，不是 GX Simulator，也没有连接实际 PLC、修改 GX 工程、解锁密码、切换 RUN/STOP 或写物理输出。下一篇使用固定版本的真实 C# 包访问这个服务端。

## MC、SLMP、以太网与 SDK 分别是什么

MC 是 MELSEC Communication Protocol。SLMP 是 Seamless Message Protocol；SLMP 中的3E/4E格式与 MC 的 QnA-compatible 3E/4E对应，并不表示所有叫 MC 的旧帧也都能按本例处理。[SLMP 规范，第2/4章](https://dl.mitsubishielectric.com/dl/fa/document/manual/plc/sh080956eng/sh080956engm.pdf)

TCP/UDP 负责传输，MC/SLMP 负责设备访问报文；二者都不是 CC-Link IE 或 EtherCAT 的运动总线周期。上位机通过 TCP 读到位置，并不代表由 Windows 网络线程负责确定性轨迹插补。

C# 可以使用第三方协议库，也可以按现场条件选择三菱提供的 MX Component。后者是另一套应用接口与部署方式，不是把本例包名换掉即可复用。[MX Component 官方说明](https://www.mitsubishielectric.com/fa/products/cnt/plceng/smerit/mx_component/)

选择之前核对：CPU/以太网模块型号及版本、实际开放的协议和端口、TCP还是UDP、帧类型、数据编码、设备指定格式、路由与写权限。能用 GX Works 下载工程，只说明工程连接可用，不能据此推断 MC 服务已配置好。

## 3E 与 4E、Binary 与 ASCII 不能只改一个字节

3E 不携带4E那样的请求序号，教学客户端坚持一个连接只有一个在途请求。超时后关闭旧连接，不能把可能迟到的旧响应当作下一次读取结果。

4E 有序号供请求响应匹配，但仍需要客户端正确管理序号、并发与生命周期；“有序号”不自动提供写入幂等。1E、串行3C/4C、iQ-R扩展设备指定等也不是给本例帧头改个名称就能支持。

Binary 把数值编码成二进制字段；ASCII 使用规定的字符编码与字段宽度。例如 Binary 请求子头字节是 `50 00`，不是 ASCII 字符 `5`、`0`、`0`、`0` 的四个字节 `35 30 30 30`。数值表示和报文编码要分别理解，不能用 UTF-8.GetString 解读整个 Binary 响应。[MC 手册，第5章](https://dl.mitsubishielectric.com/dl/fa/document/manual/plc/sh080008/sh080008ab.pdf)

## 设备不是寄存器的另一个名字

先在点位表中写清设备类型与编号，再谈 C# 类型：

| 设备例子 | 本课 Q/L 格式中的编号 | 设备单位 | 教学用途 |
| --- | --- | --- | --- |
| D100 | 十进制100 | 字设备，16位/点 | 有符号温度原始值 |
| M100 | 十进制100 | 位设备 | 内部状态或请求位 |
| X10 | 十六进制0x10 | 位设备 | 只读演示状态 |
| Y10 | 十六进制0x10 | 位设备 | 物理输出风险，本例不提供写入 |
| W10 | 十六进制0x10 | 字设备 | 链接寄存器示例 |

因此 D100 与 M100 并不是同一区域的不同类型视图；W10 的编号数值也不是十进制10。D 也没有“声明成 int 就自动只占一个点”的规则。

**不要把此表直接套用到所有 FX 型号和通信格式。** X/Y 的工程显示与协议指定可能涉及八进制、十六进制或不同格式约定，必须以具体手册及所选库的解析规则确认。本例使用的 McpX 把 X/Y/W 等字符串编号按十六进制解析。[FX5 通信格式与设备指定](https://dl.mitsubishielectric.com/dl/fa/document/manual/plcf/jy997d60801/jy997d60801g.pdf)

从旧笔记复制 X10 时，要明确它原来按什么进制解释，不能只做字符串替换。把设备编号与十六进制报文字节混为一谈，是“能通信但读错点”的常见来源。

## 字设备、位设备，与字/位访问方式

字设备 D 的一个点是16位。位设备 M 可以按单个位访问；协议也存在对位设备按字访问的方式，此时一个字对应一组位，起点、点数和对齐要求要另行核对。本轮不实现位设备的字访问。

本课批量读取命令为 `0401`，批量写入为 `1401`，Q/L基本设备指定下，字单位子命令为 `0000`，位单位为 `0001`。这是具体命令格式，不是“所有MC请求都用这个子命令”。

位单位的 Binary 数据不是 Modbus 那样每个字节紧凑放八个位：本例按每点一个半字节、先高半字节再低半字节处理。五个值 `[true,false,true,false,true]` 表达为 `10 10 10`，最后一个低半字节为填充。不能拿 `BitArray` 的紧凑位布局直接当报文。

## 看懂一次读 D100 开始的两个字

本机测试使用下列请求作为独立的核对向量：

```text
50 00 | 00 FF FF 03 00 | 0C 00 | 02 00 | 01 04 | 00 00 | 64 00 00 | A8 | 02 00
子头    本站路由          长度    监视定时器  命令    子命令    起始编号     设备码 点数
```

这里的数值字段按对应 Binary 格式解释：D100 的编号为100，所以编码为 `64 00 00`；`A8` 是本格式的 D 设备码；命令 `0401` 在线上是 `01 04`。起始编号不是 ASCII 文本 `D100`。

长度 `0C 00` 的数值为12，覆盖监视定时器到请求数据，不含前面的9字节头。定时器数值2对应500 ms的设备侧等待配置，不等于整个 C# 方法的总期限。本例包的800 ms客户端请求超时会生成该值；0有无限等待含义，不能随意设0“提速”。

路由 `00 FF FF 03 00` 是本课明确选定的直达本站CPU示例。复杂网络站号、多CPU和模块缓冲区访问不能盲目沿用，也不能把模块I/O号当 TCP 端口。

响应以 `D0 00` 开始，长度从结束码算起。结束码为0才进入正常数据解释；非0时要保留错误信息而不是继续解码成温度。写入成功响应通常没有读数据载荷。

这些字段用于看懂抓包与核对示例，不要求业务页面手写报文。项目的 `McFrames` 是教学服务端子集，不是替代经过验证的完整客户端。

## C# 类型决定取多少字，但点位契约决定怎么解释

| C#类型 | 本课占用D字数 | 例子 |
| --- | --- | --- |
| short / ushort | 1 | D100，原始0xFF85按short为-123 |
| int / uint | 2 | D101低字、D102高字，合成0x12345678 |
| float | 2 | D103/D104存放IEEE754 Single的位模式 |
| double / long / ulong | 4 | 本轮只讲宽度，不声明四字类型已实测 |

以本机数据契约为例：D101=0x5678、D102=0x1234，`uint` 为0x12345678；每个16位字内部也是低字节在前。不要把前面Modbus案例的字节/字顺序设置不加核对搬过来。

同样两个字，既可以解释为UInt32，也可以解释为Float32；协议读成功不会告诉你哪个业务解释才对。缩放、单位、有效值和浮点特殊值仍要由契约约束。

当库的 `BatchRead<int>(..., 2)` 表示两个int元素时，线上点数是4字，范围占 D120～D123，不是 D120～D121。写入也一样；写 short 与写 int 覆盖宽度不同。

## TCP分帧、非0结束码与结果未知

NetworkStream.ReadAsync 返回一次数据，不保证恰好一个 MC 帧。接收方按固定头和长度取完整帧，限制分配大小，处理半帧、EOF和等待期限；不能“延迟50ms然后Read一次”就当完整通信。

第三方库抛出的结束码异常、格式异常、超时和socket故障，要记录真实类型及阶段。非0结束码不应被转换成数值0；数值0可能是合法工艺值。

如果客户端发出写入之后连接断开，设备可能已经改值。项目专门提供“写入D110已生效，但服务端丢弃回执并关闭”的负例：客户端只知道调用失败，不能知道设备是否执行。模拟器能检查内部值，是测试端的额外证据，现场客户端没有这项特权。

因此不能盲目自动重发写入，更不能用“重连后再置一次启动位”代替去重握手。正常响应和读回一致，也还没证明PLC程序接受或机械动作完成。

## 从通信读写走向现场之前

本例只是数据访问。进入现场之前需要按型号核对支持范围、单次点数限制、周期负载与写权限，给PC独立的命令/参数区，避免覆盖PLC自身维护的状态和输出。不要为了演示成功擅自开放远程控制或关闭保护。

经典MC数据访问不能被当成OPC UA那种带证书安全通道和DataValue质量的接口。隔离网络、访问控制、采集时间与失效规则仍要单独设计；不要向公网暴露教学TCP服务。
