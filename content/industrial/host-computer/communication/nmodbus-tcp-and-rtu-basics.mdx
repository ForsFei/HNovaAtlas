## 先固定版本，再查 API

本篇选择 NModbus 作为 C# Modbus 入门库，不表示所有设备都必须用它。它提供 TCP 与串行协议等支持，当前示例只涉及 TCP 与 RTU。[项目入口](https://github.com/NModbus/NModbus)

配套项目 `examples/industrial-modbus/IndustrialModbus.csproj` 固定复现基线：

```xml
<TargetFramework>net10.0</TargetFramework>
<!-- 放在项目的 ItemGroup 中 -->
<PackageReference Include="NModbus" Version="3.0.83" />
<PackageReference Include="NModbus.Serial" Version="3.0.83" />
<PackageReference Include="System.IO.Ports" Version="10.0.0" />
```

这不是“始终最新版本”声明。示例依据实际还原的包、XML 文档与其记录的源码提交核对，不混用 NModbus4 或其他分支的工厂写法。[NModbus 包版本](https://www.nuget.org/packages/NModbus/3.0.83)、[串口适配包](https://www.nuget.org/packages/NModbus.Serial/3.0.83)

本篇交付 TCP 完整本机读写与故障检查、RTU 配置和可编译读取用法。**没有打开任何 COM 端口，也没有进行 RTU 实际收发验收**；继续阅读[数据解释、WPF 轮询与受约束写入](/knowledge/industrial/host-computer/communication/modbus-value-decoding-and-wpf-monitor/)。

## 对象关系：库不会替你完成全部生命周期

| 对象 | 怎样得到 | 做什么 |
| --- | --- | --- |
| `ModbusFactory` | `new ModbusFactory()` | 创建主站、传输等对象 |
| `TcpClient` | 建立到设备 IP/端口的 TCP 连接 | 底层网络连接 |
| `SerialPort` | 按手册配置后 Open | 底层串口，由 RTU 适配包接入 |
| `IModbusMaster` | `factory.CreateMaster(tcpClient)` | 统一调用读写功能 |
| `IModbusSerialMaster` | `factory.CreateRtuMaster(serialPort)` | RTU 主站对象，仍可调用常用读写方法 |
| `master.Transport` | 主站属性 | 读写等待、重试和异常应答处理配置 |

TCP 先 Connect，RTU 先 Open；创建 master 不是额外的设备握手。主站、底层连接/端口都应有明确 using 作用域，先结束操作再释放，不把 master 公开给多个定时器各自访问。

与上一节相比，**不要再给 NetworkStream 自己加 CRLF 组帧，也不要订阅 SerialPort.DataReceived 抢读字节**：实际 Modbus 传输由 NModbus 管理。

## 读写方法查表

下表是该版本实际可用的常用同步方法，均有相应的 Async 命名方法。参数中的 `slaveAddress` 在 TCP 示例中对应 Unit ID，在 RTU 中对应串行站号；`startAddress` 是协议偏移，不是 40001 参考编号。

| 功能 | C# 调用形式 | 结果 |
| --- | --- | --- |
| 读线圈 FC01 | `ReadCoils(unit, start, count)` | `bool[]` |
| 读离散输入 FC02 | `ReadInputs(unit, start, count)` | `bool[]` |
| 读保持寄存器 FC03 | `ReadHoldingRegisters(unit, start, count)` | `ushort[]` |
| 读输入寄存器 FC04 | `ReadInputRegisters(unit, start, count)` | `ushort[]` |
| 写单线圈 FC05 | `WriteSingleCoil(unit, address, value)` | 正常返回或抛异常 |
| 写单保持寄存器 FC06 | `WriteSingleRegister(unit, address, value)` | 正常返回或抛异常 |
| 写多线圈 FC0F | `WriteMultipleCoils(unit, start, boolArray)` | 正常返回或抛异常 |
| 写多保持寄存器 FC10 | `WriteMultipleRegisters(unit, start, ushortArray)` | 正常返回或抛异常 |

`unit` 是 byte，地址/读数量通常是 ushort；批量写入数量从数组长度得到。库负责位打包、报文构造和正常响应验证，不需要自己在 bool 后面追加 `FF00`，也不用自己在 TCP 报文后追加 CRC。

库还有读写组合与其他接口，但不能据此推断设备支持相应功能。先把常用八类和设备点位对上，再扩展。[固定提交的主站接口](https://github.com/NModbus/NModbus/blob/d96e7707a08cebe7f436087e7d575c930963d91a/NModbus/Interfaces/IModbusMaster.cs)

## Transport 的关键属性

项目在创建 master 后统一配置：

```csharp
master.Transport.ReadTimeout = 400;
master.Transport.WriteTimeout = 400;
master.Transport.Retries = 0;
master.Transport.SlaveBusyUsesRetryCount = true;
master.Transport.WaitToRetryMilliseconds = 50;
master.Transport.RetryOnOldResponseThreshold = 0;
```

| 属性 | 本篇如何理解 |
| --- | --- |
| `ReadTimeout` / `WriteTimeout` | 底层同步读写等待，单位 ms，不是整个事务或一整轮业务总期限 |
| `Retries` | 普通 I/O/超时等失败后的重发次数；本例设 0，不自动重发 |
| `SlaveBusyUsesRetryCount` | 让 Busy 06 也受次数限制；本例 true，结合 Retries=0 防止反复重发 |
| `WaitToRetryMilliseconds` | 库处理特定异常应答/重试时的等待，不能替代总期限 |
| `RetryOnOldResponseThreshold` | 旧事务响应再读策略；本例关闭，不用它隐藏关联错误 |

特别注意 Busy 与 Acknowledge：固定版本的源码对它们有专门分支，普通 Retries 并非所有等待行为的统一开关。ACK 05 可能让库继续读取后续响应；我们另外为 TCP 工作单元设置总预算。[固定版本传输实现](https://github.com/NModbus/NModbus/blob/d96e7707a08cebe7f436087e7d575c930963d91a/NModbus/IO/ModbusTransport.cs)

400 ms 是本机教学参数，不是设备推荐值；现场应结合波特率、处理周期、批量大小和网关时延确定。

## TCP：从连接到读写、读回与释放

先看对象使用主线。下面代码假设调用方已经提供 `endpoint` 和 `stop`，只连接本课程自己启动的回环设备：

```csharp
using var tcp = new TcpClient(endpoint.AddressFamily);
await tcp.ConnectAsync(endpoint.Address, endpoint.Port, stop);

using IModbusMaster master = new ModbusFactory().CreateMaster(tcp);
ModbusExamples.Configure(master);

const byte unit = 1;
ushort[] temperatureRaw = master.ReadInputRegisters(unit, 0, 1);
decimal temperature = unchecked((short)temperatureRaw[0]) / 10m;

master.WriteSingleRegister(unit, 0, 300);     // 模拟目标值 30.0
master.WriteMultipleRegisters(unit, 1, [2, 7]);
ushort[] readBack = master.ReadHoldingRegisters(unit, 0, 3);

master.WriteSingleCoil(unit, 0, true);        // 只改模拟灯
master.WriteMultipleCoils(unit, 2, [true, false, true]);
bool[] coils = master.ReadCoils(unit, 0, 5);
bool[] inputs = master.ReadInputs(unit, 0, 3);
// 退出作用域：master 和 tcp 都有明确释放边界。
```

这段展示的是同步库调用，**不能直接搬进 WPF UI 线程**。完整项目会把整个同步工作单元放在一个后台任务中，并处理总期限、取消和失败，不是只加一个 async 关键字。

在内置数据表中，温度来自 Input Register 0，目标值来自 Holding Register 0。即使地址都为 0，选择错误功能区也会读到不同数据；这正是四个区域不能混为一个数组的原因。

### 正确解释寄存器

项目的 `RegisterCodec` 没有依赖机器字节序：

```csharp
public static decimal SignedTenths(ushort raw) => unchecked((short)raw) / 10m;

public static uint UInt32HighWordFirst(ushort high, ushort low) =>
    ((uint)high << 16) | low;

public static float FloatHighWordFirst(ushort high, ushort low) =>
    BitConverter.Int32BitsToSingle(unchecked((int)UInt32HighWordFirst(high, low)));
```

例如 ushort `0xFF85` 不能直接除十当正温度，需要先按契约解释为 Int16；`41C8 0000` 在本例高字在前约定下才是 25.0。设备如果采用低字在前，不能继续照抄这个函数。Float32、Int32、标志位和字符串的完整数据解释将在后续案例继续扩展。

## Async、取消和总期限要分开看

该版本很多常用 Async 方法内部是 Task.Run 包装同步方法，并且接口没有 CancellationToken 参数。方法名带 Async 不等于它原生支持取消，也不能照搬前面原生 NetworkStream.ReadAsync 的令牌用法。[固定版本主站实现](https://github.com/NModbus/NModbus/blob/d96e7707a08cebe7f436087e7d575c930963d91a/NModbus/Device/ModbusMaster.cs)

本篇采用一个明确的 TCP 适配策略：

1. 一次预算覆盖 Connect 和整个工作委托，而不只是某一次 Read。
2. 工作任务独占 master，顺序执行同步库方法。
3. 预算到达或调用方取消时，关闭该任务专用的底层 TcpClient，让 I/O 退出；不在别处并发 Dispose master。
4. 继续 await 工作任务，等待其 using 清理完成，再返回失败或取消。

主线位于 `ModbusExamples.ExecuteTcpAsync`：

```csharp
using var client = new TcpClient(endpoint.AddressFamily);
using var budget = CancellationTokenSource.CreateLinkedTokenSource(stop);
budget.CancelAfter(timeout);
await client.ConnectAsync(endpoint.Address, endpoint.Port, budget.Token);

using CancellationTokenRegistration abort = budget.Token.Register(
    static state => ((TcpClient)state!).Dispose(), client);

T result = await Task.Run(() =>
{
    budget.Token.ThrowIfCancellationRequested();
    using IModbusMaster master = new ModbusFactory().CreateMaster(client);
    Configure(master);
    return work(master, budget.Token);
});
budget.Token.ThrowIfCancellationRequested();
```

完整方法还区分调用方取消与内部超时。这个片段不能脱离完整异常处理直接当作通用封装；也不能强行终止任意不检查令牌的 CPU 计算，或拿去保证 COM 驱动会在同样时间退出。

为什么不用 `await libraryTask.WaitAsync(timeout)` 后直接返回？因为那样可能只有等待者结束，真正的同步读取仍在后台占用流。超时后立即重用连接，会让旧读取和新请求互相争抢响应。

关闭 TCP 也不会撤回已经送达的写命令。现场写入超时时，结果可能未知；本例不会自动重发，也不把超时显示为“设备肯定没有改值”。

## RTU：更换底层对象，功能方法保持相似

RTU 使用额外的串口适配包与命名空间：

```csharp
using System.IO.Ports;
using NModbus;
using NModbus.Serial;
```

配套 `ReadRtuTemperature` 是可编译但默认不调用的例子，需要调用者以后明确选择已准备好的测试设备：

```csharp
using var port = new SerialPort(portName, baudRate, parity, 8, stopBits)
{
    Handshake = Handshake.None,
    ReadTimeout = 400,
    WriteTimeout = 400,
};
port.Open();
using IModbusSerialMaster master = new ModbusFactory().CreateRtuMaster(port);
ModbusExamples.Configure(master);
ushort[] raw = master.ReadInputRegisters(unitId, 0, 1);
decimal temperature = RegisterCodec.SignedTenths(raw[0]);
```

`portName/baudRate/parity/stopBits/unitId` 来自已确认的测试配置，不在代码里假定现场设备是 COM3 或 9600/8E1。协议数据表也必须与设备一致，不是所有设备的温度都在输入寄存器 0。

RTU 写入仍使用同一组主站方法，例如 `master.WriteSingleRegister(unitId, verifiedOffset, rawValue)`，前提是设备手册明确该地址、功能、权限和业务条件。**本轮不执行这类串口写入**。关闭时等待同步操作结束，再释放 master 和 SerialPort；不要给串口额外发送 CRLF，也不要手工为库方法追加 CRC。

RTU 没有 TCP 那样的 MBAP 事务号，同一总线上更应串行发起请求。485 接线、终端匹配、偏置与接地隔离、方向切换和串口帧时序需要按设备/转换器资料验收，不能只凭离线 CRC 函数通过就判定可用。

## 异常怎样区分

```csharp
try
{
    ushort[] values = master.ReadHoldingRegisters(1, 0, 2);
}
catch (SlaveException error)
{
    Console.WriteLine($"Function=0x{error.FunctionCode:X2}, " +
        $"Exception=0x{error.SlaveExceptionCode:X2}, Unit={error.SlaveAddress}");
}
```

例如模拟器范围只有 0～7，读 Holding Register 8 会返回 83/02，库抛 SlaveException。它与底层 IOException、SocketException、读取超时以及调用方取消不是一回事。

同样，不要把错误事务号自动视作温度，或无限读到“某个看起来合理的值”。本例关闭旧响应重读策略，检查事务关联失败并结束工作单元。

## 运行完整示例与检查

从仓库根目录运行：

```powershell
dotnet run --project examples/industrial-modbus/IndustrialModbus.csproj -- --demo
dotnet run --project examples/industrial-modbus/IndustrialModbus.csproj -- --self-test
```

不带参数也运行本机 demo。服务端在进程内绑定回环临时端口，客户端是实际 NModbus；读到温度 -12.3 °C，写入模拟目标 300、模式 2、计数 7，再读回确认。所有写入只修改模拟存储，退出不保留。

服务端独立实现八个教学功能码与有限地址范围，不是完整 Modbus 服务栈。用它验证库客户端，比只检查内存数组多覆盖了真实 MBAP、功能码、位打包和网络交换，但仍不是设备认证。

自动检查还包括：

- Int16 缩放、UInt32/Float32 高字在前、MBAP 长度与 RTU CRC 向量。
- 八种功能码、单/多点写入读回、非法地址/数量/单线圈编码。
- 非法跨界多寄存器写入不会先改掉一部分模拟值。
- Busy 的有限退出、错误事务号、对端关闭、提前取消、接收期间取消、慢字节总期限和 ACK 等待。
- 未打开串口的 RTU 工厂/属性配置检查。

测试不会访问真实 COM 或局域网设备。[后续 WPF 示例](/knowledge/industrial/host-computer/communication/modbus-value-decoding-and-wpf-monitor/)独立验证数据解释与写入结果模型；RTU 串口收发、WPF 人工操作和现场设备兼容性仍需分别验收。
