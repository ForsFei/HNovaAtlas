## 2. 常用对象、属性和方法

| 类型/成员 | 用途与边界 |
| --- | --- |
| HObject | 图像/区域/XLD等图标对象的基础包装，可包含多个对象 |
| HObject.CountObj() | 图标对象数，不是像素数或必然的连通块数 |
| HImage / GetImageSize | 面向对象图像类型与尺寸查询，不应凭空假设Width属性 |
| HImage.Threshold | 从图像得到区域，返回新对象 |
| HRegion.Connection / SelectShape | 连通区域分开与按特征选择 |
| HXLDCont | 轮廓对象，与区域/图像不同，后续轮廓专题使用 |
| HTuple.Length / Type | 有效元素数与类型，不是图标对象数 |
| HTuple.I / D / S | 相应标量访问，读取前先验证长度和类型含义 |
| HTuple.TupleReal / DArr | 转为实数元组，再访问内部double数组表示 |
| HOperatorSet | 静态算子风格，输出经out返回 |
| Dispose | 结束本调用拥有的包装器/资源引用，不能清别人仍在用的对象 |

主程序统一使用HOperatorSet，避免同一入门链中混用多种风格。面向对象方法可查[HImage](https://www.mvtec.com/doc/halcon/2411/en/HImage.html)与[区域阈值接口](https://www.mvtec.com/doc/halcon/2411/en/threshold.html)；表格是查用地图，不表示本轮把所有方法都跑过。

## 3. 从输入契约开始，而不是直接Threshold

本例复用前面原创P2夹具，固定一张8×6单通道byte图。不把文件后缀当类型证明：

```csharp
HOperatorSet.ReadImage(out image, path);
if (image.CountObj() != 1)
    throw new InvalidOperationException("只接受一张图");
HOperatorSet.GetImageSize(image, out width, out height);
HOperatorSet.CountChannels(image, out channels);
HOperatorSet.GetImageType(image, out type);
```

这些是完整函数中的片段，image等变量在函数前声明并在finally释放。width/height/channels必须是单元素元组；本例再检查8、6、1及type.S为byte。不会悄悄把RGB转灰度、把uint2缩到8位或改变输入尺寸。

ReadImage官方支持包含pgm的多种格式，但本轮没有原生库实际验证该P2文件读取，仍需native-test确认，不把此前自写P2解析器通过当成HALCON读图通过。

程序还读取neighborhood与max_connection，要求8和0，只读不改。它是隔离教学进程的前提检查，不是阻止其他线程并发改全局设置的锁；正式多算法进程需要集中管理此类配置。

## 4. 实际的算子链与参数

```csharp
low = new HTuple(200);
high = new HTuple(255);
HOperatorSet.Threshold(image, out region, low, high);
HOperatorSet.Connection(region, out components);

feature = new HTuple("area");
operation = new HTuple("and");
minArea = new HTuple(2);
maxArea = new HTuple(10);
HOperatorSet.SelectShape(components, out selected,
    feature, operation, minArea, maxArea);
```

以上真实API已针对官方24113.0.0接口编译。数值阈值来自8位夹具，不是所有工件的最佳参数；[SelectShape官方说明](https://www.mvtec.com/doc/halcon/2411/en/select_shape.html)描述按特征与区间筛选，本例只用area。

为什么先Connection再SelectShape？如果对包含多个分离部分的一个阈值区域直接按总面积筛选，就不等于逐个连通块筛选。具体该按整体还是按单块，要由任务定义，不是固定顺序能包治百病。

## 5. 没有对象与异常要走不同分支

```csharp
int count = selected.CountObj();
if (count == 0)
    return BlobReadback.FromArrays(w, h, 0, 2, 10, [], [], []);
if (count > 64)
    throw new InvalidOperationException("超出教学对象上限");

HOperatorSet.AreaCenter(selected, out areas, out rows, out columns);
```

成功处理后没有选中区域，才返回NoCandidates；不能用catch所有异常再返回NoCandidates。读图失败、库加载失败、许可失败、维度错误或元组不一致都不是“算法已执行但没找到”。

本例count=0时不调用AreaCenter，避免依赖空输入相关系统设置的行为。正面积候选要求面积至少2，不把一个空区域的(0,0,0)输出误当有效原点目标。

## 6. HTuple有效长度与内部数组容量

本轮同时核对了固定包自带XML说明：DArr暴露内部double数组，数组长度可能大于HTuple.Length，而且要求对应类型。直接把整段DArr当有效输出会带出多余容量。

实际代码先转实数，再只复制有效前缀：

```csharp
private static double[] Numbers(HTuple tuple)
{
    using HTuple real = tuple.TupleReal();
    return BlobReadback.CopyUsedValues(real.DArr, real.Length);
}
```

CopyUsedValues校验0..64与底层容量，再用AsSpan(0, usedLength).ToArray生成独立托管副本。复制后的数组不共享HTuple内部存储，不会把临时元组或原生包装器传入后续UI。

再要求areas/rows/columns长度都等于选中图标对象数量。不能只检查三个数值数组彼此一样长，却忘记与CountObj比较。面积要求有限、为整数像素数且落在筛选区间；Row/Column有限且在原图中心域。

本例所有夹具都是全图像素坐标，因此允许检查0..Height-1和0..Width-1。裁剪/重采样/其他坐标域需要另建输入契约，不能只放宽范围绕过错误。

## 7. 资源释放：不覆盖丢失旧所有者

完整函数对HObject和HTuple输出预先置null，并在finally释放已有值：

```csharp
HObject? image = null;
HObject? region = null;
try
{
    HOperatorSet.ReadImage(out image, path);
    HOperatorSet.Threshold(image, out region, 200, 255);
    // 后续使用；不要让这些原生对象逃出所有权范围。
}
finally
{
    region?.Dispose();
    image?.Dispose();
}
```

该片段仅展示图标对象顺序，完整函数还显式保存/释放参数元组、输出元组等。不要连续out到同一变量并丢掉仍需释放的旧对象；也不要返回一个已经在using/finally里Dispose的HObject。

HDevelop自动管理局部变量的体验不能直接等同于C#作用域自动确定释放。GC最终化不是高频处理的精确释放时机；同时也不应每帧GC.Collect去掩盖所有权问题。

对于本次固定接口，HTuple.Dispose的XML说明特别区分含句柄与纯数值元组：纯数值元组调用没有清句柄效果，含句柄则涉及其引用。不要笼统声称“Dispose一个数值元组就关闭采集器”或“所有HTuple都绝不影响句柄”。[ClearHandle官方说明](https://www.mvtec.com/doc/halcon/2411/en/clear_handle.html)还指出显式清除会影响仍持有引用的使用者，模型/采集器需按具体对象管理。

## 8. 托管返回值不携带原生资源

BlobReport包含源宽高、Outcome和只读BlobFeature集合，每项有AreaPixels、RowPixels、ColumnPixels。FromArrays做防御复制，调用者改输入数组不会改已发布结果。

Candidates表示存在符合本批筛选条件的候选，不是产品OK；NoCandidates也不自动等于产品NG。没有工件/帧/配方身份字段的这份小例子，不应该直接替换前面流水线中的完整结果信封。

## 10. 环境故障怎么定位

1. 先检查托管包版本与实际运行库版本是否匹配，别把旧20.11原生DLL与24.11接口混用。
2. 检查进程架构与原生库架构；本例固定x64，AnyCPU不等于自动适配全部厂商文件。
3. 检查原生库搜索路径及其依赖，使用厂商提供的正确运行环境；不要把随机DLL复制进System32。
4. 原生库成功加载后，再区分许可、格式、算子参数和输出语义错误；当前DllNotFoundException不能证明许可有问题。
5. 不安装破解/替代许可，不把环境故障改写成正常空结果；部署文件和授权按合法配套环境核对。
