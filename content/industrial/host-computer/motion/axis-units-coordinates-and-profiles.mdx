## 本章从哪里开始

后续硬件主线确定为雷赛 **E3032 总线卡**；本文按官方 DMC-E3032 系列资料建立概念，具体后缀、固件、驱动器和 SDK 版本待实机核对。脉冲卡不会略过，但作为共同概念之后的对照分支，不再与总线卡混用配置和回零流程。

本章先回答：位置的数字代表什么、谁在执行运动、怎样知道动作真正结束。下一篇查用 [E3032 SDK 接口](/knowledge/industrial/host-computer/motion/leadshine-e3032-sdk-basics/)，再用 [C# 单轴模拟](/knowledge/industrial/host-computer/motion/csharp-single-axis-simulation/)验证状态和失败路径。这里不需要连接任何控制卡，也不默认启动就使能或回零。

## 1. 上位机、控制卡、驱动器和机械轴

一条轴的主要执行链可以简写为：

```text
C# / WPF：参数、模式、命令、状态、记录
       ↓ 厂商 SDK
运动控制卡：轨迹规划、运动时序、设备接口
       ↓ EtherCAT 或脉冲/方向
驱动器：按工作模式执行控制，管理电机与驱动报警
       ↓
电机 → 联轴器/减速机构 → 丝杆或传送机构 → 负载
       ↑ 编码器、原点、限位等反馈来自各自配置的通道
```

实际位置环放在哪里、反馈怎么参与控制，要看所选模式和硬件，不是所有系统都由卡完成同样的闭环。C# 发出命令后，通常由卡和驱动器继续执行；界面是否刷新不决定伺服周期是否推进。

不要用 `Task.Delay(1)`、WPF `DispatcherTimer` 或快速循环向电机“每毫秒发一步”来代替运动控制器。UI 定时器用于展示状态，不提供确定的 EtherCAT 周期或安全停止保证。

### 总线卡与脉冲卡的共同点和差别

| 问题 | E3032 EtherCAT 主线 | 脉冲卡对照 |
| --- | --- | --- |
| 给驱动器什么 | 在配置的总线与工作模式下交换控制和反馈数据 | 脉冲数量、频率及方向，另有控制/状态 IO |
| 是否等于普通网口通信 | 不是 `TcpClient` 连一个 IP 就能代替控制卡主站 | 也不是串口向驱动器发字符串 |
| 驱动就绪怎样知道 | 总线诊断、轴状态机、报警及映射状态 | 按接线读取就绪、报警、到位等信号 |
| 位置反馈 | 核对 PDO、驱动单位与 SDK 实际含义 | 可能没有反馈，也可能有编码器反馈通道 |
| 回零 | 本系列手册包含驱动器回零接口，方法依驱动器 | 常见卡侧原点/限位搜索，按卡和接线配置 |
| 需要共同讲清 | 单位、方向、机械行程、参考点、互锁、动作身份与停止 | 同左，不因换通信方式而消失 |

总线正常不等于驱动器已经操作使能；操作使能不等于坐标已经建立；有位置数值也不等于轴的位置可信。已有 [EtherCAT 入门](/knowledge/industrial/ethercat/basic/introduction/)与 [PDO](/knowledge/industrial/ethercat/communication/pdo/)可作为背景。

## 2. 当量：把机械毫米与指令增量对应起来

先约定三个量：

- `P`：电机转一圈对应的有效指令增量，单位 count/电机圈。
- `R`：电机圈数 / 负载圈数，例如电机转 2 圈、丝杆转 1 圈，`R = 2`。
- `L`：丝杆每转一圈的位移，单位 mm/负载圈。

则：

```text
countsPerMillimetre = P × R / L
commandCounts = distanceMm × countsPerMillimetre
```

教学例：有效指令分辨率为 10000 count/电机圈，减速比按上述定义为 2，丝杆导程 5 mm，则当量为 4000 count/mm。走 12.5 mm，对应 50000 count。

注意 `P` 是**这套配置实际使用的指令单位**：脉冲驱动要结合输入脉冲与电子齿轮；总线驱动要结合驱动位置单位、电子齿轮/比例参数和卡的工程单位。不能看见“17 位编码器”就直接把 `131072` 填进所有系统。

总线手册仍使用“脉冲当量”这个术语，但不代表 EtherCAT 线上改成了脉冲接线。`dmc_set_equiv` 的参数含义是 pulse/unit；如果约定 `unit = mm`，就填对应的每毫米增量。先定义单位，再设置，并用读回及受控测量验证，不要既在 C# 乘一次当量，又向已经按毫米配置的 `_unit` 接口传入脉冲数。

### C# 换算需要考虑什么

配套示例的 `UnitScale` 独立处理换算：

```csharp
var scale = new UnitScale(4000m);
int counts = scale.ToCount(12.5m);       // 50000
decimal mm = scale.ToMillimetres(counts); // 12.5
```

它用 `decimal` 表示配置量，半个 count 按远离零取整，正负对称，并以 `checked` 拒绝 Int32 溢出。量化误差最多半个 count（数值可表示且没有溢出的前提下）。选用 Int32 是本示例契约，不意味着所有 SDK 的位置都是 Int32；实际按 API 声明选择。

毫米不能描述所有轴。旋转轴可能用角度，卷料轴可能用长度或圈数；必须在参数名、配方和日志中保留单位。精度还受机械间隙、弹性、安装与标定影响，不是小数位越多实际越准。

## 3. 机械坐标、工作坐标、绝对与相对

本文约定：

```text
工作坐标 = 机械坐标 - 工作零点在机械坐标中的位置
机械目标 = 工作目标 + 工作零点偏置
```

例如机械位置 25 mm，工件零点在机械位置 10 mm，显示工作位置就是 15 mm。修改工作零点偏置是改变坐标解释，不是让轴物理运动。

| 指令 | 在本文约定下的意思 | 从机械位置 25 mm 出发 |
| --- | --- | --- |
| 机械绝对定位到 30 | 目标是机械坐标 30 | 走 +5 mm |
| 相对定位 +30 | 在当前机械位置基础上加 30 | 到机械坐标 55 |
| 工作绝对定位到 30，偏置为 10 | 应用先换算为机械目标 40 | 走 +15 mm |
| 设置工作偏置为 20 | 改显示参考，不发运动 | 机械位置仍是 25 |

SDK 的绝对定位使用哪个位置计数器，需要查 API；它不会自动认识应用里的“当前工件零点”。相对运动遇到重复提交可能多走一次，不能因回执丢失便重发。参见[动作身份与断线去重](/knowledge/industrial/host-computer/communication/device-command-handshake-and-idempotency/)。

### 把位置清零等于回零吗

不等于。写位置计数器只是重新标记数字；回零是通过约定的传感器、索引或驱动参考机制，建立坐标与机械基准的联系。绝对值编码器系统也要有自己的参考有效性与多圈数据恢复策略，不能简单套用“每次上电必回零”或“有绝对值就永远不回零”。

模拟器保留一个独立 `Homed` 标志；没建立参考时，即使能显示 20 mm，也不允许一般定位。本例的这个策略不代表所有现场手动模式都必须如此。

## 4. 速度、加速度、加速时间和短行程

若 `unit = mm`，位置为 mm、速度为 mm/s、加速度为 mm/s²、加加速度（jerk）为 mm/s³。雷赛本章涉及的 `dmc_set_profile_unit` 接收的 `Tacc/Tdec` 是**秒**，不是加速度数值。把 `100 mm/s²` 原样填到 `Tacc` 会完全改变运动意图。

下面只推导零起速、零末速、加减速度恒定的理想点位运动，不把它当作厂商 S 曲线或全部工作模式的公式：

```text
加速距离 sa = v² / (2a)
减速距离 sd = v² / (2d)
若距离 s >= sa + sd：能达到设定速度，中间匀速
否则：峰值速度 vp = sqrt(2s / (1/a + 1/d))，没有匀速段
```

25 mm、最大速度 10 mm/s、加减速度均 100 mm/s²：加减速各 0.1 s、各走 0.5 mm，匀速走 24 mm，用时 2.4 s，总计 2.6 s。距离缩到 0.1 mm 时，只能形成三角曲线，达不到 10 mm/s。

S 曲线用更平滑的加速度变化减小激励，具体参数定义、最短段行为、起停速度和模式兼容性应按卡的手册验证。提高速度和加速度前还要检查电机转速、负载惯量、转矩、机械允许值与停止空间，不能只看界面输入范围。

## 5. 回零为什么单独做成一个动作

回零需要明确：搜索方向、原点/限位接线与有效电平、初始已经压住传感器如何退出、快速搜索与慢速复寻、是否找编码器索引、零点偏移、超时和失败后参考是否有效。

E3032 主线先查驱动器支持的回零方法及卡的 `nmc_set_home_profile`、`nmc_home_move`、`dmc_get_home_result`。不能把脉冲卡的卡侧回零设置照搬过去，更不能把某个示例的回零方法号直接用于所有伺服。

“回零函数返回成功”表示调用被接受的层面；“轴停了”也可能是限位、报警、外部停止或搜索失败。只有匹配本次动作、明确回零成功、状态和反馈条件成立时，才更新应用的参考有效性。

模拟器仅演示从正侧向零点单阶段搜索，不能演示完整回零方式；初始在零点或负侧会拒绝，避免用一个立即清零掩盖真实回零的复杂度。

## 6. 定位结束：指令位置、反馈位置和到位

指令位置是规划/指令侧的位置；反馈位置是从实际配置的反馈通道取得的位置。两者可能存在跟随误差。不能将指令位置复制一份就标成“编码器实际位置”。

一个应用侧定位成功条件通常要联合判断：本次命令已接受、没有被中止、规划已结束、没有报警/限位/总线故障，且按设备约定满足反馈误差与到位条件；必要时还需稳定持续时间。取哪个通道、误差阈值多少、到位信号怎么配置，都属于设备契约。

没有反馈时应明确写“指令侧完成”，而不是宣称机械到位。SDK 的 `dmc_check_done = 1` 表示指定轴已停止，不能单独作为上述成功判据。

## 7. 普通停止、限位、急停和恢复

普通减速停止仍有停止距离。理想恒减速度且不考虑延迟时，`s = v² / (2d)`；实际还要加入识别、通信、控制响应、负载及机械因素，不能拿这个公式直接替代安全距离计算。

- 软件行程限制依赖可信的坐标和正确配置；回零失败、计数器被改写时尤其要谨慎。
- 硬件限位是否直接进入卡/驱动器、极性、停止方式和退出方向，需要按接线与参数验证。
- SDK 的立即停止或名称含 `emg` 的软件函数，不因此成为认证急停功能。安全回路、STO、制动器和防护设计应按设备风险评估及厂商要求完成。
- 垂直轴断使能可能失去保持力；普通关闭软件或异常清理不能随意替代受控停止和抱闸顺序。

报警复位只表示尝试清除对应故障，不应顺便使能、回零或重发上一个运动。总线丢失时，PC 可能不知道轴是否停止；恢复通信后先读真实状态、确认机械环境和参考，不把旧 UI 快照当成现场事实。

## 自测与面试追问

1. 4000 count/mm 配好后，向 `_unit` 绝对定位接口传 12.5，为什么不能再乘 4000？
2. 工作零点改了，机械位置是否变化？相对定位为什么不能在超时后盲目重试？
3. 短距离为什么达不到设置的最高速度？`Tacc` 与加速度分别是什么单位？
4. 总线正常、操作使能、已回零、已停止、到位分别证明什么？
