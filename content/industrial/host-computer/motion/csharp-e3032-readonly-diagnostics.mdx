## 本例不是另一个运动模拟器

[上一批单轴模拟](/knowledge/industrial/host-computer/motion/csharp-single-axis-simulation/)验证回零、定位和停止状态；这一批新增 `examples/industrial-leadshine-diagnostics/`，只验证“怎样读、怎样核对、怎样让失败的读数失效”。

项目固定 .NET 10，无第三方包、网络、P/Invoke 或硬件开关。唯一后端是 `FakeReadOnlyDmc` 测试替身，不加载 LTDMC.dll，也不模拟 EtherCAT 或伺服。本批已经通过 **81 项应用层检查**；尚无用户版本的原生 SDK 后端，不能宣称 E3032 真实读取已验证。

## 1. 先运行一次

从仓库根目录执行：

```powershell
dotnet run --project examples/industrial-leadshine-diagnostics/IndustrialLeadshineDiagnostics.csproj -c Release -- --self-test
dotnet run --project examples/industrial-leadshine-diagnostics/IndustrialLeadshineDiagnostics.csproj -c Release -- --demo
```

demo 读取虚构卡3/轴0的指令位置12.5，接着把替身设为轴故障并再次读取，最后关闭并确认快照不再有效。命令行只接受这两个模式，不提供 IP、卡号或 `--hardware` 参数，所以不会误连现场设备。

## 2. 为什么只保留一个小接口

`IReadOnlyDmc` 是应用自己定义的边界，不是原生 DLL 的函数声明。它包含资源初始化/关闭、卡列表和当前章节需要的只读函数，不包含使能、运动、复位、清错、配置下载或写 IO。

普通读取统一返回 `ApiValue<T>`，分别携带 `Code` 与 `Value`。初始化仍直接返回卡数量/特殊结果；没有把它强行包装成“0成功”。将来用配套官方 `LTDMC.cs` 实现这个接口，采样层不需要知道原生数组、指针和调用约定。

这里不做通用插件系统、多个运动品牌的抽象框架或自动故障恢复。整个项目要求一个调用者串行拥有同一个 SDK 资源域；没有实现多所有者锁、跨进程仲裁或原生调用线程安全保证。

### 对应官方 SDK 的函数地图

| 应用接口 | 对应官方函数 | 返回值处理 |
| --- | --- | --- |
| `BoardInit` | `dmc_board_init` | 返回卡数量/特殊结果，不按0成功处理 |
| `BoardClose` | `dmc_board_close` | 检查错误码；不是停止接口 |
| `Cards` | `dmc_get_CardInfList` | 检查返回码及数量、类型/ID数组边界 |
| `ControllerMode` | `nmc_get_controller_workmode` | 输出0仿真/1 EtherCAT，读取不切换 |
| `BusError` | `nmc_get_errcode` | 返回码和输出诊断分别检查 |
| `SlaveCount` | `nmc_get_total_slaves` | 输出从站数，不证明完整身份 |
| `AxisCount` | `nmc_get_total_axes` | DWORD总轴数，含虚拟轴 |
| `AxisType` | `nmc_get_axis_type` | 按本手册校验期望EtherCAT类型1 |
| `AxisNode` | `nmc_get_axis_node_address` | 保存从站地址和子轴地址 |
| `DriveState` | `nmc_get_axis_state_machine` | 输出本SDK的0～7枚举 |
| `AxisError` | `nmc_get_axis_errcode` | 轴诊断值与函数返回码分开 |
| `Equivalent` | `dmc_get_equiv` | 当量为pulse/unit，必须有限且为正 |
| `CommandPosition` | `dmc_get_position_unit` | 指令位置，不命名为实际编码器位置 |
| `CommandSpeed` | `dmc_read_current_speed_unit` | 单轴速度unit/s，不据此证明机械静止 |

函数语义按[雷赛官方 EtherCAT 总线卡手册](https://www.leisai.com/upload/file/2025/07/31/%E9%9B%B7%E8%B5%9B%E6%8E%A7%E5%88%B6EtherCAT%E6%80%BB%E7%BA%BF%E5%8D%A1%E7%94%A8%E6%88%B7%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C20250728.pdf)核对；真实接入仍必须核对用户配套包装层。原生数组容量、字符串缓冲、位数、调用约定和线程要求不是这个接口能够自动解决的。

## 3. 真实包装层应怎样接，而不是怎样猜

下面是未来实现接口时的一段接线形态：将原生输出参数和返回码整理为应用结果。它假设 `LTDMC` 声明与下方调用一致；**当前项目没有包含该类型，片段没有针对用户 SDK 编译或执行**。

```csharp
// 放在实现 IReadOnlyDmc 的真实后端中；不是当前可运行项目的硬件入口。
public ApiValue<ushort> BusError(ushort card, ushort port)
{
    ushort diagnostic = 0;
    short rc = LTDMC.nmc_get_errcode(card, port, ref diagnostic);
    return new ApiValue<ushort>(rc, diagnostic);
}

public ApiValue<NodeAddress> AxisNode(ushort card, ushort axis)
{
    ushort slave = 0, subAxis = 0;
    short rc = LTDMC.nmc_get_axis_node_address(card, axis, ref slave, ref subAxis);
    return new ApiValue<NodeAddress>(rc, new NodeAddress(slave, subAxis));
}
```

不通过反射去猜方法、不自行声明一套未经核对的 P/Invoke，也不从网上挑选同名 DLL 让它“先跑起来”。`Cards` 的数组/数量读取尤其应严格按官方包装层和手册要求实现；初始化失败后是否需要额外清理，也要在固定版本下验证。

尽管称为只读诊断，真实后端的初始化/关闭仍会操作 SDK 资源；应在明确的资源所有权、设备状态和现场许可下接入，不能旁路关闭另一个控制程序正在使用的卡。本批没有执行这些真实调用。

## 4. 配置预期值，不自动认领读到的设备

`ProbeConfiguration` 保存卡ID、固件类型、逻辑轴、节点/子轴、从站数、当量及最大采样时长。类型名 `FirmwareType` 对应卡列表中固件类型含义，不是完整硬件型号或固件版本；真实适配还需补齐版本记录。

测试夹具中的卡3、轴0、节点1001/子轴0、从站2、当量4000和类型0x1234全部是虚构数据。**0x1234不是E3032产品编码**，不能照抄到真实配方。

接口先检查配置范围：卡号0～7、轴号小于255、从站数非0、当量有限且为正、采样预算在本例允许范围内。轴号255因其他接口存在全轴语义而被本例策略拒绝；这不是对所有型号最大轴数的断言。

`Open()` 分配资源后核对：返回卡数量有效、卡列表数量相符、卡ID无重复，并存在期望ID和固件类型。之后还没有生成位置快照，更没有使能任何轴。

## 5. 一次采样到底读什么

`Sample()` 在第一次读取前先将 `Latest` 清空，随后按顺序执行：

1. 读控制器模式，期望为 EtherCAT，而不是自动切换。
2. 读总线诊断；函数调用错误与输出诊断非0分别报告。
3. 核对预期从站数和轴号范围；不把总轴数当物理伺服数。
4. 核对轴类型和节点/子轴映射。
5. 核对当量，拒绝无穷、NaN、非正和不符配置的值。
6. 读轴状态、轴错误、指令位置和速度，拒绝未知枚举和非有限数值。
7. 再读轴映射与总线诊断，发现部分采样期间变化。
8. 核对采样耗时，通过后一次性发布不可变快照。

这里的“一次性发布”只是应用对象的交接，**不意味着这些 SDK 读取来自同一个 EtherCAT 周期**。前后检查也检测不了所有瞬变、变化后又恢复，或地址不变的设备替换。需要更强一致性和设备身份时，应按具体 SDK/设备能力另外设计。

### 数据有效为什么可以同时有报警

测试中轴状态7、轴错误17仍可生成新鲜快照，因为它准确描述“此刻读到了故障”；这不是运动许可。反过来，总线诊断或映射检查失败时，本例拒绝发布位置快照，用异常和 `LastFailure` 保存失败信息。

不要把 `Latest != null` 或 `IsCurrent == true` 直接绑定为“可以运动”。本例没有安全输入、完整驱动反馈、回零结果和机械互锁数据，无法做这类判断。

## 6. 常用对象的实际用法

以下片段在本项目内使用，与CLI相同，只访问测试替身：

```csharp
var api = new FakeReadOnlyDmc();
using var probe = new CardProbe(api, FakeReadOnlyDmc.Configuration);
probe.Open();

ProbeSnapshot sample = probe.Sample();
bool fresh = probe.IsCurrent(sample, TimeSpan.FromSeconds(2));
Console.WriteLine($"card={sample.Card.Id}, axis={sample.Axis}, fresh={fresh}");
Console.WriteLine($"command={sample.CommandPosition}, axisError={sample.AxisError}");

probe.Close();
// 关闭使Latest失效；此前持有的sample也不再是当前有效观察。
```

| 对象成员 | 用来做什么 | 不能推导什么 |
| --- | --- | --- |
| `IsOpen` | 资源会话已建立 | 总线正常、已使能或已回零 |
| `Latest` | 最近一次完整发布的快照 | 数值永远新鲜 |
| `LastFailure` | 最近采样/初始化失败信息 | 自动修复或停止已经完成 |
| `Sample(token)` | 执行一次串行采样 | 后台自动轮询、自动重试 |
| `IsCurrent(sample, maxAge)` | 同一会话的当前快照仍在年龄预算内 | 跨设备原子一致性或运动许可 |
| `Close/Dispose` | 使观察失效并尝试释放资源 | 真实机械轴已停止 |

## 7. 时间、取消和原生调用卡住的问题

快照记录采样开始/结束UTC时间用于追踪，也记录同一 `TimeProvider` 的单调时间戳用于耗时和年龄。新鲜度从**最早读数**开始计算，避免长采样结束后把整批值看成刚刚产生。`IsCurrent` 还要求快照就是当前 `Latest` 且会话代次匹配。

每次同步调用前后检查取消。取消在调用过程中到达，要等它返回后才能观察；不声称 `CancellationToken` 可以强行中止原生函数。采样超预算也只能在调用返回后拒绝发布，不能解除一个永远不返回的驱动调用。

因此不使用 `Task.WhenAny(timeout)` 丢下仍在后台读卡的任务，也不在同一会话上并发重新读取或关闭。如果实际 SDK 存在阻塞风险，需先查超时能力、线程约束和厂商支持，再决定是否需要进程隔离；这不是在教程里增加一个 `Task.Run` 就能解决的问题。

## 8. 出错与关闭如何收尾

初始化一旦尝试，失败时本例也进行一次资源清理；如果初始化与清理都失败，用 `AggregateException` 保留两个错误。这个清理策略仍需真实 SDK 验收，不代表所有版本的初始化失败都具有完全相同的资源行为。

采样失败或取消清空 `Latest`，后续明确调用 `Sample` 可以再次尝试只读诊断；没有自动轮询、复位或重放动作。关闭先使观察失效，再检查关闭结果。

如果关闭结果不明确，当前实例不再自动初始化，也不盲目重试全局关闭。异常不会被伪装成停止成功。生产集成还需要在最外层同时保留业务异常和退出清理异常；不要让 `using` 清理抛出的异常覆盖排查所需的原始记录。
