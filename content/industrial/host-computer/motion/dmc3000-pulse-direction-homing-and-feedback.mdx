## 这一章在总路线中的位置

用户的实际硬件主线仍是E3032总线卡；这里把脉冲卡作为独立对照补完整，不把总线工程切换一个布尔值就称为兼容脉冲卡。

资料基线为[雷赛DMC3000系列官方手册](https://www.leisai.com/upload/file/2025/07/31/DMC3000%E7%B3%BB%E5%88%97%E7%94%A8%E6%88%B7%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C20250710.pdf)，所查正文标示V2.0。下文页码为正文印刷页码。DMC3400A、DMC3600、DMC3800、DMC3C00及不同固件存在差异，不能把系列名当成统一能力声明。

本章没有打开控制卡、写IO或输出脉冲；具体接线端子、电气规格和驱动器参数，须按所用板卡、接线板、驱动器的完整型号核对。可运行的是下一篇的[C#纯数值示例](/knowledge/industrial/host-computer/motion/csharp-dmc3000-pulse-io-and-position-contracts/)。

## 1. 脉冲卡向驱动器传递什么

脉冲数量表达指令位移，脉冲频率表达指令速度；方向按所选输出模式表示。驱动器按自己的输入方式和电子齿轮解释指令，再结合电机与负载执行。

因此应分开核对：

- 指令链：卡的输出方式、驱动输入方式、有效沿/电平、电子齿轮和机械传动。
- 控制与状态链：使能、就绪、报警、到位、原点、限位和急停相关信号。
- 反馈链：是否有实际可用的编码器/驱动脉冲反馈、接到哪个通道、采用何种计数方式。

驱动器内部有编码器，不代表卡或C#已经读到该编码器。卡发完脉冲也不等于负载已经到位。

## 2. 单脉冲加方向与双脉冲

手册8.2节、表8.1列出了本系列的输出方式0～5。按图可归纳为：

| 方式组 | 表达方向的方法 | 图中的区别 |
| --- | --- | --- |
| 0/1 | PULSE输出脉冲，DIR高为正向、低为负向 | 脉冲空闲电平不同 |
| 2/3 | PULSE输出脉冲，DIR低为正向、高为负向 | 与0/1的方向电平关系不同 |
| 4/5 | 正向由PULSE端输出脉冲，负向由DIR端输出脉冲 | 双脉冲，空闲电平不同 |

图中0/2/4空闲电平为高、1/3/5为低。最终使用哪种方式，必须匹配驱动接收定义、有效沿、电气接口和方向要求；不能只记“模式0就是所有雷赛卡默认通用方案”。

`dmc_set_pulse_outmode`用于设置，`dmc_get_pulse_outmode`用于读回。读回一致只说明配置的一部分，不验证真实接线或机械方向。

机械正方向由工位坐标约定，不能与电机顺/逆时针或DIR的高/低电平直接画等号。不要用修改原点开关极性的办法去“修正运动方向”。

## 3. 指令当量、电子齿轮和输出频率

沿用[当量基础](/knowledge/industrial/host-computer/motion/axis-units-coordinates-and-profiles/)的定义：

```text
指令pulse/mm = 每电机圈有效输入脉冲数 × 电机圈/负载圈 ÷ 每负载圈位移mm
输出pulse/s  = 指令速度mm/s × 指令pulse/mm
```

教学例：每电机圈有效输入10000 pulse，电机/丝杆转数比2，导程5 mm，则4000 pulse/mm。12.5 mm对应50000 pulse，20 mm/s对应80000 pulse/s。

这里的有效输入脉冲数已经包含所选驱动输入与电子齿轮的影响，不能再重复乘一次电子齿轮或编码器倍率。实际允许频率、脉宽、方向建立时间、电机转速和机械允许值还需分别核对；卡的API上限不能代表驱动或机构也允许。

本章常用的 `dmc_pmove` 位移为pulse，`dmc_set_profile` 速度为pulse/s、Tacc/Tdec为秒。这与E3032主线的 `_unit` 工程单位调用不同。参数是double，也不意味着单位自动变成毫米。

## 4. 原点、限位和状态极性

先确定信号接到卡、驱动器还是扩展模块，再核对有效含义。`dmc_set_home_pin_logic`设置ORG有效电平，所查手册规定其filter参数为保留值0；不能自行把它当可调的毫秒滤波时间。

`dmc_set_el_mode`分别配置限位使能、有效电平和制动方式。软件行程限制还要核对位置来源是指令计数器还是编码器计数器，并确保参考和缩放可信。

### 电压电平、开关触点和SDK状态不是同一层

常开/常闭触点是接线和器件关系，高/低有效是输入解释，`dmc_axis_io_status`则返回手册定义的运动信号状态位。不能把SDK已经解释过的ON/OFF位再按原始电平极性反转一遍。

正负限位同时有效应保留为异常诊断，排查映射、接线和机构；不能靠软件挑一个方向让它继续走。缺少或未确认的信号也不能默认显示为“正常”。安全回路和硬件保护另行设计，不由普通状态解码器提供安全保证。

## 5. 卡侧回零与E3032驱动回零的区别

E3032主线通过 `nmc_set_home_profile/nmc_home_move`将相关回零参数交给驱动器，见[驱动回零专题](/knowledge/industrial/host-computer/motion/e3032-drive-homing-and-reference/)。本章卡侧回零入口则是 `dmc_set_homemode/dmc_home_move`，对应卡的原点、限位和索引配置。

手册8.3节常用参数：

| 字段 | 本手册含义 | 容易混淆的地方 |
| --- | --- | --- |
| `home_dir` | 0负向、1正向 | 不是模型常用的-1/+1 |
| `vel_mode` | 0低速、1高速的选择器 | 虽声明double，不是填写一个实际速度值 |
| `mode` | 卡侧回零方法号 | 不与总线驱动器方法号共用 |
| `EZ_count` | 保留参数，固定0 | 不是任意设置索引脉冲个数 |

本手册的低速模式取前面 `dmc_set_profile` 设置的起始速度，高速模式取最高速度。不要将全零曲线与低速选择器直接复制到设备，也不要以为它与总线回零的Low_Vel/High_Vel字段完全相同。

### 先理解几组方法，不盲记数字

0～2是原点搜索/回找相关方式；3～5涉及原点与EZ组合或单独EZ；6～9涉及锁存；10～12为限位回零相关方式。精确轨迹、初始已压开关的处理和偏移时序要看对应方法说明。

所查手册还注明：方式4固定为低速回零，部分DMC3C00轴只支持特定方法，10～12存在固件条件。不能根据“总共12轴”便推断每条轴都支持所有回零和锁存功能。

遇限位是否反找、原点与索引的映射、初始开关条件，都是回零契约的一部分。不能在遇限位后由C#无限发反向指令来替代卡的受支持回零流程。

### 偏移与清零时序

`dmc_set_home_position`将是否清零与偏移的先后顺序区分为不同模式，并对限位回零的偏移方向提出要求；具体值和单位仍按所用函数/版本核对。不要将它等同E3032驱动器的Offsetpos，也不要因位置参数是double就当作毫米。

`dmc_set_position`、`dmc_set_encoder`修改计数器，不是搜索机械基准。启动时无条件将两者清零，会掩盖参考未知，还可能改变软件限位的意义。

## 6. 编码器倍率必须单独核对

手册8.16节的 `dmc_set_counter_inmode`：0为非A/B的脉冲/方向方式，1/2/3分别为1×/2×/4×A/B计数。**四倍计数的参数值是3，不是4。**

只有明确规格中的PPR表示每圈周期数而非已经折算后的计数值时，才能据此乘计数倍率。反馈可能来自驱动器处理后的输出，也不一定是内部绝对编码器的原始分辨率。

于是必须建立两套契约：

```text
指令通道：pulse/mm、正方向、参考计数、补偿阶段
反馈通道：count/mm、正方向、参考计数、补偿阶段
```

跨功能的轴号尤其要查表：某些型号拥有的脉冲轴多于对应编码器输入；所查编码器API中参数8在部分型号表示手轮通道，不能当成“第九条伺服轴的反馈”。板卡型号、具体轴和功能资源要一起核对。

## 7. 为什么不能直接相减两个计数值

先按各自比例、方向和参考转换为共同机械坐标，才有比较意义：

```text
commandMm  = (commandCount - commandOrigin) × commandSign / commandCountsPerMm
feedbackMm = (encoderCount - encoderOrigin) × encoderSign / encoderCountsPerMm
difference = commandMm - feedbackMm
```

除此之外还要确认时间与表示阶段。所查手册说明：启用螺距补偿时，`dmc_get_position`读补偿前指令位置，而 `dmc_get_encoder`读补偿后编码器位置；另有扩展接口区分相应读数。不能在这种情况下无条件相减并命名为“跟随误差”。

即使电机编码器反馈与指令一致，也不能据此证明负载端没有间隙、打滑或联轴器问题。无反馈或基准未确认时，显示未知与证据级别，不填零，也不复制指令位置冒充反馈。

## 8. 实机前的对照验收

| 项目 | 核对内容 |
| --- | --- |
| 型号/固件/SDK | 轴数、编码器通道、方法和API声明是否匹配 |
| 电气与方向 | 接口规格、脉冲模式、有效含义、机械正向 |
| 单位 | 指令与反馈各自缩放、倍率和参考 |
| 回零 | 初始开关状态、方法轨迹、索引、偏移与失败处理 |
| 状态 | 就绪/报警/到位真实来源，缺失信号保持未知 |
| 完成与停止 | 本次动作身份、停止原因、位置/反馈证据，取消等待不算停止 |
