## 回零不是把位置框写成零

在[坐标基础](/knowledge/industrial/host-computer/motion/axis-units-coordinates-and-profiles/)中，回零的目标是建立机械基准与坐标的关系，不是显示一个数字0。知道轴当前的位置值，不等于知道它与工位、限位或夹具的真实关系。

本章围绕 E3032 总线卡的**驱动器回零**展开，兼顾脉冲卡的卡侧回零。接口按雷赛官方手册核对；用户配套 SDK、伺服型号和固件尚未提供，因此没有执行原生调用或机械动作。下面涉及参数写入和回零的 C# 片段仅为接口导读，不是运行即启轴的程序。

## 1. 谁在搜索原点

总线方案的典型流程是：应用通过卡的 SDK 配置回零参数，卡将相关参数传给驱动器，由驱动器执行该方法。原点、限位和索引信号从哪里来，以及驱动器怎么处理它们，取决于接线、驱动参数和所选方法。

脉冲卡的卡侧回零则由卡按其原点/限位输入、回零方式和速度曲线规划脉冲运动。相似的“回零”按钮，不代表底层使用同一函数、同一信号或同一方法号。

| 问题 | E3032 总线驱动回零主线 | DMC3000 脉冲卡侧回零对照 |
| --- | --- | --- |
| 谁执行回零步骤 | 驱动器按支持的回零方法执行 | 控制卡按卡侧配置执行 |
| 方式参数入口 | `nmc_set_home_profile` | `dmc_set_homemode` 等 |
| 开始动作 | `nmc_home_move` | `dmc_home_move` |
| 结果入口 | `dmc_get_home_result` | 同名结果接口，仍按版本核对 |
| 首先核对什么 | 驱动支持列表、信号来源、单位与偏移 | 卡输入映射、极性、方式和脉冲单位 |

资料依据：[雷赛 EtherCAT 总线卡手册](https://www.leisai.com/upload/file/2025/07/31/%E9%9B%B7%E8%B5%9B%E6%8E%A7%E5%88%B6EtherCAT%E6%80%BB%E7%BA%BF%E5%8D%A1%E7%94%A8%E6%88%B7%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C20250728.pdf)7.5、8.4节与 [DMC3000 系列手册](https://www.leisai.com/upload/file/2025/07/31/DMC3000%E7%B3%BB%E5%88%97%E7%94%A8%E6%88%B7%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C20250710.pdf)回零章节。下文页码为正文印刷页码。

## 2. 按方法需要的信号选，不按示例号码选

常见搜索思路包括：搜索原点开关边沿、结合限位建立搜索方向、找到原点后再找编码器索引，或仅寻找索引。部分驱动还支持把当前位置声明为原点的方式，它没有搜索机械开关，因此必须有其他依据保证当前机械参考正确。[驱动器方法差异示例](https://doc.synapticon.com/node/sw5.6/motion_control/operation_modes/homing_modes.html)

雷赛手册第79页的示例采用方式33直接找EZ，但第188页明确说明后续模式图以松下A6B为例，其他品牌查对应驱动器手册。**不能因看见33能运行，就让所有伺服都采用33。** 用户具体伺服未确定时，本课程不替用户选现场方式号。

建立一行可审查的回零契约：

```text
轴/驱动型号 → 支持的方法号及名称 → 搜索方向
→ 使用的开关/边沿/索引 → 初始条件 → 速度与时间参数及单位
→ 原点偏移语义 → 正常完成证据 → 失败/中止后的参考策略
```

### 原点开关与EZ索引有什么差别

原点开关提供机械范围或边沿参考；编码器索引与转动位置有关，可能每转出现一次。若机构需要在多圈范围内确定一个唯一位置，只找周期性索引未必足够，须结合机构、开关或已有绝对参考。重复定位精度也不只由“有没有EZ”决定，还受机械、信号、搜索方式和驱动配置影响。

搜索方向、开关极性和初始是否压住开关共同决定轨迹。初始就在开关上，可能需要按方法先退出再复寻；不能用“当前开关有效，就直接设零”替代该方法规定的步骤。

## 3. 回零参数对象应该包含什么

手册第187～188页列出：

```text
nmc_set_home_profile(CardNo, axis, home_mode,
                     Low_Vel, High_Vel, Tacc, Tdec, Offsetpos)
nmc_get_home_profile(CardNo, axis, ref home_mode,
                     ref Low_Vel, ref High_Vel, ref Tacc, ref Tdec, ref Offsetpos)
```

| 参数 | 手册给出的含义 | 配置时应补齐的信息 |
| --- | --- | --- |
| `CardNo / axis` | 卡号与总线轴号 | 与已核对的映射一致，禁止误用全轴值 |
| `home_mode` | 总线轴回零模式 | 驱动型号/固件是否支持、实际搜索步骤 |
| `Low_Vel / High_Vel` | 回零低速/高速 | 实际单位、适用阶段、机械允许值 |
| `Tacc / Tdec` | 回零加速/减速时间 | 时间单位和驱动解释，不能填加速度值 |
| `Offsetpos` | 回零偏移 | 单位、符号、是否产生物理偏移、最终坐标如何定义 |

特别注意：所查版本8.4节参数表**没有逐项标出这些数值的单位**。不能仅因普通定位使用 `_unit` 接口，就断言这里的 `500` 一定是500 mm/s，也不能认为设了当量后所有驱动回零参数自动成为毫米值。需核对配套 SDK/驱动资料和受控验证结果后再填值。

配置应保留机械层意图与 SDK 参数之间的换算依据，例如“期望搜索速度、驱动采用的实际单位、转换后的参数、依据版本”。参数读回一致能证明配置读写的一部分，不等于接线、运动方向或机械位移已经验证。

## 4. C# 参数写入、读回与启动的边界

以下假设使用配套官方 `LTDMC` 声明，`approved` 表示已经审核且单位明确的参数，不是项目中现成的可运行类型。**片段未针对用户 SDK 编译或执行。**

```csharp
// 参数写入属于单独的受控配置步骤，不放在每次启动的自动流程中。
short rc = LTDMC.nmc_set_home_profile(card, axis, approved.Mode,
    approved.LowVelocity, approved.HighVelocity,
    approved.AccelerationTime, approved.DecelerationTime, approved.Offset);
if (rc != 0)
    throw new InvalidOperationException($"Set home profile: {rc}");

ushort mode = 0;
double low = 0, high = 0, tacc = 0, tdec = 0, offset = 0;
rc = LTDMC.nmc_get_home_profile(card, axis, ref mode,
    ref low, ref high, ref tacc, ref tdec, ref offset);
if (rc != 0)
    throw new InvalidOperationException($"Read home profile: {rc}");
// 对照审核值/驱动量化规则核对读回；不自动进入使能或回零。
```

提交回零是另一个动作步骤，需先完成卡身份、总线、驱动实际使能状态、机械空间、模式与互锁等检查。驱动状态输出4是本SDK的OP_ENABLE枚举，不是总线OP，也不是原始状态字等于4。

```csharp
// 仅展示调用形态。调用方已取得单轴所有权，且现场动作条件另行确认。
short rc = LTDMC.nmc_home_move(card, axis);
// rc==0只作为本次调用已确认的证据，不在此处置Homed=true。
// 调用结果不明时保留原动作记录，不自动重发。
```

读结果时分开检查返回码和输出状态：

```csharp
ushort homeState = 0;
short rc = LTDMC.dmc_get_home_result(card, axis, ref homeState);
if (rc != 0)
    throw new InvalidOperationException($"Read home result: {rc}");
if (homeState is not (0 or 1))
    throw new InvalidOperationException($"Unknown home result: {homeState}");
// 0未完成，1完成。仍须核对是否属于本次动作及当前状态。
```

不要在UI线程忙等，也不照搬老示例中的 `Application.DoEvents()`。真实轮询应由资源所有者串行执行，采用明确期限和采样质量；取消等待不会自动向卡发送停止。

## 5. 上一次HomeDone为什么危险

调用前可能已经读到 `homeState=1`，也可能轴从头到尾都处于停止。若发出新请求后立刻读一次1就完成，很可能把旧结果当成新结果。

所查接口表只说明0/1含义，并未提供与应用请求号绑定的回零事务ID，也没有证明每种驱动/方法都会在应用的采样窗口内出现一次0。不能自行编一个“清HomeDone”函数，或为清状态而改位置计数器。

下一篇的教学观察策略面向**有可观察运动过程的搜索式回零**：本次调用确认后，要求观察到运动、回零未完成，再观察到停止和回零完成，且没有异常停止证据。它是保守的应用规则，不是厂商保证。

如果动作太快、采样错过启动、结果位始终不清，或者所用方法根本不运动，这个观察器会拒绝确认，最终给出Unknown。它不证明设备失败，也不证明没执行；需按实际 SDK 能提供的模式/状态/结果语义完善专用判据，不能只把超时调大或盲目重发。

## 6. 三种“零点”和偏移不要叠加

1. 机械基准：开关、索引或其他可信参考所定义的机械位置。
2. 回零坐标/偏移：驱动与卡按该方法建立坐标时对偏移的处理。
3. 工件工作零点：应用为当前工件设置的坐标偏置。

雷赛手册特别提示不同驱动对回零偏移处理不同。要明确偏移是改变坐标标签、回零后继续物理偏移，还是由特定方法作其他处理；不要看到参数名Offset就假定行为。

例如工件零点在机械坐标10 mm，是应用工作偏置的含义，并不要求每次回零后再自动移动10 mm。反过来，如果驱动回零流程已处理偏移，应用再补走相同距离可能造成重复偏移。

参考有效性应由独立状态记录：是否已通过本次回零/参考恢复验证、属于哪个配置与会话、何种变化会使它失效。本教学策略在失联、参考不明或回零中止后不自动恢复参考；绝对值系统的持久参考需另按编码器、驱动和机械恢复契约处理，不能一概清零或一概信任。

## 7. 失败和恢复怎样验收

| 场景 | 要观察/记录 | 不应出现的自动行为 |
| --- | --- | --- |
| 初始未压住原点 | 实际搜索方向与信号顺序 | 未核对方向就高速搜索 |
| 初始已压住原点 | 所选方法的退出/复寻过程 | 直接将当前位置认作新原点 |
| 原点或索引缺失 | 驱动/卡诊断、行程与超时结果 | 无限搜索、无限重试 |
| 限位/报警/急停出现 | 停止原因、驱动状态、机械实际状态 | 清错后立刻续跑或反向退限位 |
| 操作员要求停止 | 单独停止请求与停止观察 | 原回零最终被标成成功 |
| 通信中断或软件等待取消 | 结果未知和现场核对需求 | 把本地任务结束当成机械停止 |
| 修复后重做 | 故障条件、参考状态和新动作记录 | 自动重放旧命令 |

验收应保留完整型号/版本、方法与参数、初始条件、信号变化、指令与可确认反馈、结果、停止原因和实际机械观察。不要通过屏蔽限位/安全输入来制造“回零成功”；异常场景测试本身也要有受控方案。

## 8. 脉冲卡后续怎样展开

DMC3000 分支还要讲原点与限位输入、电平、卡侧回零方式、速度参数、遇限位反找及偏移/清零模式。不同子型号支持范围与默认行为有差异，不能把一个卡型的设置直接用于另一款。

例如该手册的 `dmc_set_home_position` 将清零和偏移时序分开描述，不能等同于E3032驱动回零的 `Offsetpos`。虽然结果读取同名，也不代表回零动作和信号接线可以通用。具体脉冲接口细节在独立分支展开，本章不让它冒充已经验收的总线回零实现。
