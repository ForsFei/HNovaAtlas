## 恢复的对象不只是一个轴

[单轴手动恢复](/knowledge/industrial/host-computer/motion/e3032-manual-jog-interlocks-and-recovery/)解释了清错不等于重新使能、回零和重放。本篇把范围扩展到完整工艺：旧动作是否发生、哪些轴仍被占用、工件在哪里、触发是否已经发出、图像是否已归档，以及下一份计划是否还成立。

接口依据为[官方EtherCAT总线卡固定手册](https://www.leisai.com/upload/file/2025/07/31/%E9%9B%B7%E8%B5%9B%E6%8E%A7%E5%88%B6EtherCAT%E6%80%BB%E7%BA%BF%E5%8D%A1%E7%94%A8%E6%88%B7%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C20250728.pdf)正文V2.0的9.7、9.16节；本课仍是E3032基本单轴/插补主线，不扩展成E5000连续轨迹控制器。

下一篇[C#恢复复核与过期确认](/knowledge/industrial/host-computer/motion/csharp-recovery-review-and-stale-confirmation/)有59项离线检查，仅记录证据与确认，不发停止、复位、运动或拍照命令。

## 1. 先给“暂停”一个明确含义

| 操作 | 应用层含义 | 机械是否已经停止 |
| --- | --- | --- |
| 暂停接单 | 不接受新工件/任务 | 不一定，旧任务可能继续 |
| 在工步边界暂停 | 当前允许完成的工步结束后不进入下一步 | 要看工步内容及实际状态 |
| 禁止后续意图 | 当前流程不再产生新动作请求 | 已提交运动/触发不因此撤销 |
| 请求减速停止 | 向对应运动资源发送普通停止请求 | 需继续观察和核对 |
| 连续轨迹暂停/续走 | 支持设备保留未完成轨迹的专用行为 | 不属于本课E3032的通用恢复接口 |
| 安全停止/急停系统动作 | 经过设计验证的设备安全功能 | 按安全设计及验证，不由PC状态名证明 |

一个UI按钮可以触发某个经过定义的流程，但不能只改`IsPaused=true`就显示“设备已暂停”。也不能先取消后台Task，再把任务退出误认为机械已停。

工艺中哪些步骤允许完成后暂停、哪些情况必须立刻走审核后的停止流程，要依据负载、夹具、垂直轴、工件和触发链规定，不存在通用“暂停时所有输出都关掉”的规则。

## 2. E3032不能套用连续轨迹 startlist 续走

固定手册9.7节明确列出E1000/E3000不支持该节连续插补指令，其中包括`dmc_conti_pause_list`及`dmc_conti_start_list`。支持设备上，暂停与重新启动未完成缓存轨迹有特定语义；不能因为同一个LTDMC头文件有声明，就把它作为E3032通用暂停/恢复方案。

该节某些说明又出现“适用于所有插补”的宽泛表述。本课不以这句话覆盖整节型号限制；E3032基本插补按9.16节的`dmc_stop_multicoor`处理停止，并保留实际配套版本确认。

把基本点位或圆弧停下来后，再重新提交目标，是一次**新动作**，不是自动继续卡侧旧轨迹。旧命令身份、速度规划、起点及可能发生的触发都需重新解释。

## 3. 停止请求与停止证据分开记录

固定手册区分：

- `dmc_stop`：单轴/PVT停止，stop_mode为0减速、1按手册命名的紧急停止。
- `dmc_stop_multicoor`：插补坐标系停止，0减速、1立即停止。
- `dmc_emg_stop`：卡级所有轴操作，影响范围更广，不是按某个任务精确取消。

这些SDK名称和返回码并不自动等同于经认证的安全停止。普通停止也不应简单用关闭板卡、撤使能或断电替代，尤其要核对垂直轴/制动器的机械后果。

最小交接过程可以这样理解：

```text
中断意图/异常出现
  → 禁止产生后续动作，保存原任务和已尝试请求
  → 按运动模式及资源所有权请求审核后的停止
  → 观察对应轴/坐标系、反馈、报警与停止原因
  → 核对触发/输出、工件与在途图像
  → 重新确认参考、配置和资源所有权
  → 显式记录复核结论
  → 另行审核新计划；本链条不自动启动它
```

停止调用返回0只是调用确认。非0返回、调用异常或通讯中断也不能一律认定停止没有发生；应保留结果未知，并由控制器/驱动/安全系统承担各自既定责任。PC进程卡死时，本课程的定时检查不能独立发出停止。

## 4. 停在哪里与为什么停，同样重要

`dmc_check_done`适用于单轴/PVT，`dmc_check_done_multicoor`用于插补；它们返回的0/1是状态，不是常规错误码。一个轴已停止，不能替代整个坐标系或其他独立轴的判定。

`dmc_get_stop_reason`提供停止原因。固定手册中13为命令立即停止、14为命令减速停止，两者都不代表原目标完成；限位、报警、跟随误差和回零中断也不能混成“正常到位”。先保留原始诊断，再决定是否需要清除，不为让界面变绿而覆盖证据。

此外，“速度读数为0”“驱动已使能”“SDK轴状态为OP_ENABLE”“坐标系未运行”“旧任务不再占用资源”是不同维度。前几项不能单独证明后几项，更不能证明机械连续静止或场景安全。必须按具体设备建立停止/稳定及资源交接判据，本轮不实现真实判据。

## 5. 四类中断现场，不用同一个恢复按钮

| 中断位置 | 需特别保存/核对的证据 | 不应直接做什么 |
| --- | --- | --- |
| XY独立定位只有X已确认，Y结果未知 | 两轴各自的尝试、当前运动/反馈和停止证据 | 将整组视为未执行再重发 |
| 圆弧途中停止 | 停止位置、参考、方向、原圆心与工件状态 | 原参数不变就当作“剩余圆弧” |
| 比较已发生、图像迟迟未到 | 比较/边沿/相机触发身份及在途帧 | 超时就自动补发一次触发 |
| 重新连接或人工干预后恢复 | 会话代、位置与参考、实际工件去向、资源所有者 | 把重连成功当成旧任务可以续走 |

工件已取走、隔离、重新夹持或由人工移动后，即使坐标数字相同，业务现场也已经改变。工件标识与物理位置的对应关系必须重新建立。

## 6. “重新规划”不是目标减当前位置这么简单

相对运动已部分执行时，重新发送原位移可能多走一段；收到超时也无法知道剩余位移。如果要从现场位置重新定位，应先建立可用的参考、当前状态和经过审核的新路径，不在异常处理catch中直接补发。

圆弧尤其如此：停止后的实际位置可能偏离原参考圆；人工移动可能改变起点，方向选择可能使剩余路径绕过另一侧。新的速度起始条件、减速余量、工具/工件形状和空间障碍都要重新评估，不能只把终点保留下来。几何检查见[直线与圆弧](/knowledge/industrial/host-computer/motion/e3032-line-and-arc-geometry/)，它也不承担真实避障。

新计划应有新的动作身份，记录与旧任务的交接关系。旧任务保持当时的Completed/Stopped/Unknown等历史，不因新任务完成而被改成“旧任务也成功”。

## 7. 参考、清错、使能和回零独立处理

清停止原因、清SDK轴错误、驱动故障恢复、使能、回零和工作坐标建立不是一个原子操作。故障源未解除时反复清错通常没有意义，还可能丢失排障信息。

参考有效性可能受掉电、回零中断、计数器设置、当量/补偿改变或人工移动等影响，具体按位置反馈及设备实现判断。程序中的“曾经HomeDone”不能无限期沿用。

需要重新回零时，也必须先确认工件、夹具和回零路径允许；不能把回零当作无副作用的诊断读取。恢复流程不默认执行回零，更不自动重新使能或释放制动器。

## 8. 拍照已发生时，恢复还要处理什么

[单拍证据](/knowledge/industrial/host-computer/motion/csharp-trigger-and-frame-evidence/)中的Unknown可能意味着“已经触发但图像身份不足”，不意味着“肯定没拍”。迟到图像、旧缓存及重启计数都要记录，不能给旧帧重新贴上当前工件标签。

允许重拍时，应由工艺明确决定：旧图和新图如何标识、旧结果如何保留、是否需要回到专门拍照位置、是否允许多次曝光/光源动作、工件是否还保持原姿态。新拍摄是一项新业务动作，不能由PC等待超时自动触发。

比较器停用、点表清除、锁存复位、相机取消采集和运动停止分别有不同效果；其中任一返回成功，都不能推出整条链已没有残留事件。连续缓存发生溢出时，更不能简单把队列重新排齐继续按顺序配图。

## 9. 恢复前的九项复核与工件决定

下一篇将复核摘要表达为九项事实，它们由外层观察/现场程序确认，不由一个SDK读数直接生成：

| 事实 | 应确认的内容 |
| --- | --- |
| 相关轴已观察停止 | 范围明确、观测有效，满足所用设备的停止/稳定判据 |
| 坐标系已交接 | 旧任务/模式不再阻碍新资源申请，不仅是某次done=1 |
| 故障已复核 | 故障源、诊断与处置结论明确，不仅是清错误码 |
| 参考已确认 | 当前参考/当量/坐标定义与计划一致 |
| 触发已受控 | 旧触发源、比较计划及接收端状态经审核 |
| 旧拍摄已对账 | 发生/未发生/无法确认均有明确处置，不留暗中的自动补拍 |
| 工件已核对 | 当前标签与实物去向有依据 |
| 输出已复核 | 各负载按规程保持/处理，不统一等于全OFF |
| 资源独占明确 | 手动、自动、PLC、调试工具不能竞争同一资源 |

还要显式决定旧工件是保留供新计划审核，还是已经移除/隔离。选择处置项只是记录结论，不替人移动实物；移除旧工件也不会自动创建替代工件任务。

这份表并非完整安全清单。即使九项满足，只能进入**新计划复核**，仍不提供机械安全许可或实际运动授权。仅结束旧工件记录、而不准备新计划的流程，也不必假装已经完成全套新计划条件。

## 10. 确认必须对应仍有效的依据

操作员看到“可复核”后，连接、参数、参考或工件状态可能又改变。确认请求必须带上当时的复核依据；依据改变时，旧确认不能用来推进新现场。

相同实质依据在连续有效的新采样中保持，可保留已记录确认，避免每个UI刷新都重新确认。但采样过期、质量失效或中间出现缺口后，即使数字恢复成原样，也必须重新建立依据。

这些约束只是防止应用误用旧状态，不能保证人在确认后到机械执行前现场永不变化。真正派发新动作前仍需由对应所有者复核实时条件；本课没有提供该派发器或安全功能。
