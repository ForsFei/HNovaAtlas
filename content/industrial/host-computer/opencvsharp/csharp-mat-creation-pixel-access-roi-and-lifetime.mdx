## 2. Mat常用属性和方法

| 成员 | 作用与注意点 |
| --- | --- |
| Rows / Cols、Width / Height | 图像矩阵尺寸，不是控件尺寸 |
| Dims | 维数，本例仅二维 |
| Type() / Channels() | 组合类型与通道数，不自动保证颜色语义 |
| ElemSize() / ElemSize1() | 每像素/每通道字节数 |
| Total() | 元素数量，不把通道另算成像素 |
| Step() / IsContinuous() | 行距与连续性 |
| Empty() / IsDisposed | 无有效数据与包装已释放，不能混为一种状态 |
| At&lt;T&gt; / Set&lt;T&gt; | 按已核对的像素类型访问；不是任意类型自动转换 |
| Ptr(row) / Data | 原生地址，必须保证生命周期和布局有效 |
| Clone / CopyTo | 复制像素，注意目标别名和所有权 |
| Dispose | 释放自己拥有的包装/原生引用 |

本文以固定包XML、真实编译与对应版本源码为准；在线API文档可能随项目发展变化，不能把新版本成员直接当本例都支持。[固定版本Mat源码](https://github.com/shimat/opencvsharp/blob/4.13.0.20260627/src/OpenCvSharp/Modules/core/Mat/Mat.cs)

## 3. 创建和读取

```csharp
using Mat empty = new();
using Mat image = Cv2.ImRead(file, ImreadModes.Grayscale);
using Mat color = new(1, 1, MatType.CV_8UC3, new Scalar(10, 20, 30));
```

程序读取输出目录里的已知PGM文件，核对非空、6行8列、CV_8UC1，再读At&lt;byte&gt;(1,1)=220以及(4,7)=255。调用At时先行后列，不能把Point的x/y习惯照搬过来。

Grayscale是明确解码意图，不等于所有读入图都自动保持原始位深。本例夹具本身8位，其他模式/高位深图像应按需求选择并在解码后核对，不默默截成byte。[解码模式和返回值](https://docs.opencv.org/4.13.0/d4/da8/group__imgcodecs.html)

## 4. ROI：先校验，再创建共享视图

```csharp
PixelLayout.ValidateRoi(image.Cols, image.Rows, 1, 1, 2, 2);
using Mat roi = new(image, new Rect(1, 1, 2, 2));
using Mat deep = roi.Clone();
roi.Set(0, 0, (byte)42);
```

ROI输出尺寸2×2，但Step仍为父图行距8。真实检查确认IsSubmatrix为true、IsContinuous为false；改ROI局部(0,0)后，原图(1,1)变42，此前deep仍为220。

本例的检查函数拒绝空ROI、越界与负坐标，不自动裁剪。上限与拒绝策略属于教学适配器，不是声称OpenCV内部不支持任何空范围。若允许裁剪，应在业务结果中明确实际区域，不能把裁完的局部结果当原配方完整覆盖。

## 5. 正确复制非连续Mono8

CopyMono8首先检查非空、二维、CV_8UC1，然后缓存Rows/Cols/Step，逐行复制有效列：

```csharp
long stride = mat.Step();
int rows = mat.Rows, columns = mat.Cols;
byte[] packed = new byte[size];
for (int row = 0; row < rows; row++)
    Marshal.Copy(mat.Ptr(row), packed, row * columns, columns);
```

size先经PixelLayout验证得到rows×columns。缓存尺寸避免每次循环条件都跨原生接口；本例保留包分析器与警告即错误设置，没有压制相关诊断。

这里只支持正步长Mono8。三通道、16位、空Mat都明确拒绝，不自动转换或猜测类型；逐行Ptr从原生Mat取得，调用期间借用者必须保证mat不被释放、重建或并发修改。

PixelLayout对外部字节布局可核对最小长度(height−1)×stride+width，最后一行无需尾部padding。但CopyMono8依据Mat头部推导的范围本身，不能证明任意外部指针真的有那么多有效内存；本例只对自己已建立/解码的Mat演示，不包装相机外部缓冲。

## 6. Clone、CopyTo与父对象

```csharp
using Mat destination = new();
deep.CopyTo(destination);
```

本例空destination得到独立像素，之后修改deep不影响destination。没有对重叠ROI、目标与源已经共享内存等情况作通用保证。

SurvivingRoi函数内部创建OpenCV拥有数据的parent，再返回新的ROI包装；parent头部释放后，返回ROI仍通过原生引用计数保留数据。该案例实际读取到9，但不涵盖SDK借用内存或手动释放的指针。

Mat alias=image只用于ReferenceEquals检查，不另行Dispose alias，因为它是同一个包装。教学代码没有依赖“重复Dispose大概没事”来分配所有权。

## 7. 三通道和位深转换

```csharp
Vec3b bgr = color.At<Vec3b>(0, 0);
using Mat gray = new();
Cv2.CvtColor(color, gray, ColorConversionCodes.BGR2GRAY);

using Mat high = new(1, 1, MatType.CV_16UC1, new Scalar(1000));
using Mat scaled = new();
high.ConvertTo(scaled, MatType.CV_8UC1, .1);
```

原生检查确认Vec3b三个值10/20/30、灰度22、16位读取1000、缩放后100。另测不加alpha直接转8位结果255，说明不是自动按整图动态范围显示。

这里颜色和位深转换只用已知小图，不处理Bayer、线性/非线性颜色空间、相机黑电平、12位packed解包或HDR。不要把CV_16UC1误认为能直接包装Mono12Packed；后者需要先按设备格式解析。

## 8. 读取与写出的四个接口

| 接口 | 输入/输出 | 本批状态 |
| --- | --- | --- |
| Cv2.ImRead | 文件→Mat | PGM实际验证 |
| Cv2.ImDecode | 编码字节→Mat | PNG实际验证 |
| Cv2.ImEncode | Mat→编码字节 | PNG实际验证 |
| Cv2.ImWrite | Mat→文件 | 用法导读，未写文件 |

```csharp
bool encoded = Cv2.ImEncode(".png", destination, out byte[] png);
using Mat decoded = Cv2.ImDecode(png, ImreadModes.Grayscale);
```

编码后检查成功标志/字节，再解码并逐像素比较。PNG是无损格式，本批2×2 Mono8往返相同，不代表任意格式都无损、保留全部元数据或全部位深。

文件保存的一般形式是Cv2.ImWrite(outputPath, image)，应检查返回值并处理异常、权限、目录、磁盘和覆盖策略。本文不提供自动覆盖用户路径的入口，也不把内存编码通过写成已验证磁盘保存。[编解码接口参考](https://docs.opencv.org/4.13.0/d4/da8/group__imgcodecs.html)

## 9. using与返回值所有权

MatBasics用using管理解码图、ROI、Clone、转换目标和解码目标，程序结束时按作用域归还。返回给业务的CopyMono8结果是独立byte数组，不携带Data/Ptr或Mat。

如果函数返回新Mat，调用者必须接管并Dispose；如果只是借用输入，函数不能擅自释放它。不要在using中创建Mat后原样返回，又让调用者使用已经释放的对象。

MatExpr等运算临时对象也可能占用原生资源。本批不使用长运算符链，不以using Mat result等一句话就宣称所有中间对象都被正确释放。跨线程、模型缓存、WPF图像转换与长期内存观察后续再做。
