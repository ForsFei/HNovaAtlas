## 从软件知识走向设备应用

这条路线面向使用 C# 开发工业上位机的人：已经学过语言和 WPF，希望进一步理解软件如何与 PLC、运动控制卡、相机及机器人协作。应用层以 C# / WPF 为主，围绕设备读写、运动、检测和流程组织内容；进入具体 SDK 时再固定设备型号、驱动和运行环境。

## 三条技术主线与贯穿实践

| 主线 | 学习范围 | 希望最终能完成的任务 |
| --- | --- | --- |
| 工业通信 | 串口与 RS-232/485、TCP/UDP、Modbus、PLC 协议、OPC UA、厂商 SDK | 解释一条数据的来源和含义，完成读写、超时处理与连接恢复 |
| 运动控制 | 轴与坐标、雷赛单轴和多轴、IO、状态与动作流程；扩展 PLC 运动和机械臂集成 | 按设备状态发出动作请求，判断完成条件，处理异常和恢复 |
| 机器视觉 | 成像与坐标基础、HALCON、OpenCvSharp、YOLO 的 C# 部署 | 从图像得到可解释的检测结果，再把结果交给设备流程 |
| 贯穿实践 | 手动/自动状态、动作握手、配方、报警、日志、测试和部署 | 将三条主线组成可观察、可排障的小型设备应用 |

先从通信进入，再学习以雷赛为主的运动控制，随后补视觉和综合实践。章节可以按工作需要调整，但通信请求的成功、控制器接受指令和机械动作完成，要始终分别判断。

## 先分清几个容易混淆的边界

### 接口、传输和设备协议

RS-232/485、TCP、Modbus 与厂商 SDK 分别回答不同层次的问题。学习时会先说明连接与传输，再说明报文、数据类型和业务含义；例如 Modbus 的串行链路规范与 TCP 实现指南就属于不同的配套文档。[Modbus 官方规范](https://www.modbus.org/modbus-specifications)

### 上位机与运动控制器

上位机负责界面、参数、任务编排与状态监控，运动执行还涉及控制卡、PLC 或机器人控制器。雷赛产品同时存在脉冲型和 EtherCAT 总线型；本课程按用户硬件方向，以 **E3032 总线卡为主线，脉冲卡作为对照**，先讲共同概念，再进入对应 SDK。具体功能与接口仍按完整型号和版本核对。[雷赛控制卡产品说明](https://www.leisai.com/product/product_details_1412.html)

PLC 会在通信章节讨论数据访问，在运动章节讨论动作执行和握手。机械臂以发那科/爱普生为背景，先学习六轴通用基础、上位机任务集成、坐标与结果交互；暂无型号，品牌接口随实际控制器扩充。

### 视觉算法与 C# 应用

HALCON 路线包含 HDevelop 算法验证和 C# 集成；OpenCvSharp 路线包含 OpenCV 算法及 .NET 资源管理。YOLO 路线侧重模型部署，计划采用 ONNX 与 ONNX Runtime 的 C# 接口，训练和导出的必要工具作为配套内容。[HALCON 集成方式](https://www.mvtec.com/products/halcon/features-tools/development-tools-programming/hdevengine)、[OpenCvSharp](https://github.com/shimat/opencvsharp)、[ONNX Runtime C#](https://onnxruntime.ai/docs/get-started/with-csharp)

## 每一步怎样学习和验收

每个专题按“问题与概念 → 最小可运行示例 → 边界与现场故障 → 自测追问”展开。协议帧、坐标变化等适合对照观察的地方再加入交互，代码与说明保持可直接阅读。

通信优先用本地模拟设备验证数据、超时与重连；运动先验证状态和指令契约，再按型号做实机验收；视觉先用可重复的离线图片，再接相机与设备流程。每份示例会说明需要的硬件、SDK 或模型，以及实际验证到了哪一步。

综合案例计划采用一个小型检测工位：接收到料信号，运动到位，触发采图，完成判定，交接处理结果并记录追溯信息。过程中逐步加入互锁、超时和恢复条件，控制系统规模随内容交付增长。
