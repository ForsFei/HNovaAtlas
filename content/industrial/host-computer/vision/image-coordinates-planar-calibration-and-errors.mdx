## 先确定“这个点在哪个坐标系”

前面已经有自有图像、单拍关联和[有界处理](/knowledge/industrial/host-computer/vision/bounded-processing-preview-and-result-handoff/)。现在进入测量最容易出错的一步：算法返回一个点，怎样得到有明确含义的物理坐标？

本批先讲固定成像几何下的二维平面换算，配纯C#三点仿射与检查点示例。它不求镜头内参、不消畸变、不做手眼标定，也不向雷赛/PLC/机器人输出运动。普通相机保持通用路线，不要求某个品牌、SDK或标定板型号。

## 1. 五种坐标不要共用一个“X、Y”

| 坐标域 | 本文约定/含义 | 常见错误 |
| --- | --- | --- |
| 原图像素 | Column向右，Row向下；整数位置表示像素中心 | 把行列反过来，或把像素数当毫米 |
| 裁剪图局部像素 | 相对当前ROI左上角，需要还原到父图 | 裁剪后直接套原图标定 |
| 显示坐标 | 控件/画布坐标，受缩放、留白、DPI等影响 | 鼠标位置直接当原图像素 |
| 目标平面毫米 | 某个具名工件/平台平面的Xmm、Ymm | 只写mm，不说明原点、正向和所在平面 |
| 机械/机器人坐标 | 轴坐标、基座/工具/工件坐标等 | 把二维测量值直接当机械目标 |

示例用ImagePoint(Column, Row)与PlanePoint(Xmm, Ymm)分开表示。目标平面的原点与正方向必须由外部定义；“X向右、Y向上”可以是一种约定，但不能因为屏幕看起来如此就认定机械轴也如此。

所有原图点限定在中心域：Column从0到Width-1，Row从0到Height-1，允许小数。它不是整个像素面积的边界域；上边缘-0.5之类的位置不在示例支持范围内。亚像素坐标也不代表已经获得亚像素的物理测量精度。

## 2. ROI、缩放与半像素约定

若软件裁剪ROI为(X=100,Y=50,Width=200,Height=100)，裁剪图点(Column=20.5,Row=10.25)还原为原图(120.5,60.25)。仅裁剪、未缩放时，就是加父图偏移。嵌套裁剪需要逐级加回，不能漏掉中间一级。

一旦发生缩放、旋转、镜像或图像矫正，就不再是简单加偏移。尺寸比、像素中心/边界约定、重采样对齐方式必须一致；本批代码不实现resize或控件坐标逆变换，后续WPF显示单独处理留白与比例。

不同视觉库还有自己的约定。例如HALCON的图标数据变换涉及Row/Column传参顺序，部分算子区分像素中心与角点坐标；其[仿射拟合说明](https://www.mvtec.com/doc/halcon/2411/en/vector_to_hom_mat2d.html)及[AffineTransPixel说明](https://www.mvtec.com/doc/halcon/2411/en/affine_trans_pixel.html)明确提示这些差异。不能把本文Column、Row系数表不经核对直接交给HALCON，更不要机械地给所有坐标加0.5。

本示例只做原图像素中心点到物理平面点的数值换算，不做图像重采样，也不实现HALCON的像素变换约定。

## 3. 三种“标定”解决的问题不同

| 类型 | 主要回答什么 | 不能替代什么 |
| --- | --- | --- |
| 相机/镜头几何标定 | 成像模型、内参、畸变及各视图外参 | 不会自动知道雷赛轴或机器人基座 |
| 固定平面映射 | 某种图像坐标到指定平面坐标的对应关系 | 不能自动恢复未知高度或完整3D姿态 |
| 手眼标定 | 相机与机器人末端/基座之间的空间关系 | 不能只靠一张二维三点表完成 |

OpenCV的[相机标定教程](https://docs.opencv.org/4.13.0/dc/dbb/tutorial_py_calibration.html)介绍内参、径向/切向畸变和已知图案对应点。物理尺寸来自参考物的已知尺度，不是相机看到一张棋盘就天然知道毫米。

一般透视成像中，一个像素对应一条空间视线，缺少深度/平面等条件，不能仅凭这个像素唯一确定3D点。固定平面映射相当于增加了“目标点在这个已知平面上”的约束；工件高度变化后，原约束可能不成立。

手眼问题要结合机器人位姿、标定目标在相机中的位姿与明确的变换方向；参考[OpenCV手眼接口说明](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)。本批没有这些输入，不把二维换算命名为“六轴手眼完成”。机械坐标背景可复习[六轴坐标与TCP](/knowledge/industrial/host-computer/motion/six-axis-robot-frames-posture-and-modes/)。

## 4. 先选模型，不先背“九点标定”

### 单一比例尺

在成像比例近似均匀、方向已对齐、畸变/透视影响满足误差要求的局部任务中，可以用固定mm/pixel做简单长度估算。但它没有自动解决平移、旋转、非等比例缩放或斜切。

例如图像横向每像素0.1mm、纵向每像素0.2mm，两点相差(10,10)像素。物理长度是sqrt(1²+2²)≈2.236mm，不是把14.142像素乘0.1得到1.414mm。处理一般方向的长度，应先转换两端点再求距离。

### 二维仿射

本文使用：

```text
Xmm = a × Column + b × Row + tx
Ymm = c × Column + d × Row + ty
```

六个参数可以表达平移、旋转、不同方向比例与斜切，保留直线和平行关系。它不能表达一般透视下平行线汇聚，也不能把径向畸变自动消掉。是否能用于原始图像，只能由成像条件与独立误差验证决定；不因选择了远心镜头就免除验证。

### 平面单应性

一般平面透视可考虑投影模型：

```text
denominator = h31 × Column + h32 × Row + h33
X = (h11 × Column + h12 × Row + h13) / denominator
Y = (h21 × Column + h22 × Row + h23) / denominator
```

它有尺度自由度，通常用至少四组非退化对应点估计；点数够仍可能分布退化、匹配错误或不适用。OpenCV的[单应性教程](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)解释了平面之间的投影关系。镜头畸变、非共面目标和分母接近零等问题不会因此自动消失。

本轮代码**只实现三点仿射**，不提供单应性、内参拟合、RANSAC或生产级多点最小二乘。“九点”只是采样数量/流程的俗称，不能说明使用了什么模型，也不是准确性的保证。

## 5. 为什么三点必须不共线

每组二维对应点提供X、Y两条方程，三组提供六条方程。但若三个源点在一条直线上，就没有足够的二维几何信息确定可逆平面变换。目标点退化成直线时，示例也拒绝，因为后续需要反向换算。

接近共线也危险：求解对点位误差敏感。三点都挤在很小区域，即使代数可解，也不能据此推断整个视野可靠。应让真实采样覆盖工作区域，并检查几何分布、重复定位和参考坐标可信度。

示例分别对源图三角形与目标平面三角形做尺度归一化后检查形状，并加最短边策略。它只是防止教学数值退化，不是标准规定的标定精度阈值，也不能代替生产库的条件数分析或鲁棒拟合。

## 6. 数值可计算范围不等于经过验证的工作区

数学上的仿射式可以计算图像以外的点，但这叫外推，不等于有依据的测量。本例只接受拟合三个图像点的三角形及其边界，反向转换也使用对应三角形范围；图像内部但三角形外仍拒绝。

这个限制有意保守。例如训练点为(0,0)、(7,0)、(0,5)，点(7,5)虽然在8×6图像内，仍不支持。检查点也不能偷偷扩大支持范围。边界比较有小量浮点容差，但不是允许机械越界的物理裕量。

三角形内部可计算也不表示每个位置都达到精度要求。真实工作区还受检查点覆盖、畸变、光学清晰度、工件高度/平面度和任务容差限制，应单独定义并验收。

## 7. 三个拟合点误差为零，为什么不值得庆祝

精确三点模型会穿过输入三点；它们的拟合误差接近零是代数结果。若参考点本身错了，模型仍可能“完美拟合”。拿这三点再计算一次误差，不能证明泛化能力。

应另外准备未参与拟合的检查点，并尽量覆盖实际工作区，包括边缘和关键工位位置。检查点参考值要有可靠测量依据，不是用同一个模型算出来再回填。实际还需要分时段、重复装夹、不同工件高度等与任务相关的验证。

本例拒绝检查点复用训练名称或完全相同的像素位置，也拒绝检查点重复；但换名称、换位置并不能让不可信数据自动变成独立实测数据。真实性、测量溯源与点位提取仍由外部负责。

## 8. 正确读一份平面误差报告

对第i个检查点，定义误差为“模型预测减独立参考”：

```text
dx_i = predictedX_i - referenceX_i
dy_i = predictedY_i - referenceY_i
radial_i = sqrt(dx_i² + dy_i²)
RMS_mm = sqrt(sum(dx_i² + dy_i²) / N)
Max_mm = max(radial_i)
```

同时保留每点残差与X/Y有符号平均值。RMS小可能掩盖局部较大误差，因此还要看最大值和空间分布；有符号误差有助于发现系统偏差，但正负抵消后的均值不能代表整体精度。

注意单位：这里是目标平面毫米误差，不是相机标定常见的像素重投影误差。二者描述不同空间，不能直接拿0.1px和0.1mm互相比较。也不能将RMS当作95%置信区间、最大误差保证或重复性指标。

示例检查点故意加入参考偏移，报告RMS约0.045092mm、最大0.06mm。它不提供自动Pass：没有用户工艺公差、参考测量不确定度、覆盖范围与验收规则，就不能说“精度已达标”。

## 9. 点位误差怎么传到毫米

固定仿射线性部分记为A，像素扰动向量为δp，则δworld=A×δp。示例用Frobenius范数给出保守上界：

```text
若 sqrt(deltaColumn² + deltaRow²) <= epsilonPixels
则平面扰动长度 <= sqrt(a²+b²+c²+d²) × epsilonPixels
```

这是固定数学模型对输入点扰动的放大界，不包含标定参数误差、参考物误差、镜头残余畸变、热漂移、机械重复定位或高度变化。epsilon=0只表示这一项贡献为0，不意味着系统没有误差。

另外，“每轴都可能±0.2px”与“二维扰动长度不超过0.2px”不同。前者最坏二维长度约0.282843px；不能把每轴界限直接当成二维半径。

## 10. 什么时候要复核或重新标定

更换相机/镜头、改变焦距/对焦、相机或工件平面位置变化、工作高度变化、传感器ROI/binning/尺寸变化、软件旋转/镜像/缩放、去畸变流程变化，都可能影响几何关系。需要评估影响、更新配置依据并重新验证，而不是仅看文件名是否相同。

本例绑定SetupId、GeometryRevision、PixelSpace、PlaneFrame、Width/Height。任一不符拒绝转换。它们只是应用元数据，代码不会检测镜头是否被拧动、工件是否翘起或配置标签是否撒谎。

通信重连不必然改变物理几何，也不必然保持它；不能仅凭“重连成功”决定标定有效。应外部复核实际设备身份与设置，维护几何版本及验证记录。本示例没有持久化、自动复核或标定批准流程。

## 11. 坐标出来以后，先不要让轴去那里

平面点只在具名平面中有效。运动还需要平面到机械坐标的变换、机械参考/单位、Z高度、工具偏置、构型、路径、限位、互锁及任务交接。目标位置正确也不保证途经路径安全。

同理，二维点加一个角度也不等于六轴完整位姿。本批不生成E3032目标、不调用机器人SDK，不把误差报告当运动许可。它先补齐测量数据契约，之后综合工位再明确连接边界。

## 12. 复习与面试追问

1. 为什么同一像素不能直接确定一个3D点？一般透视缺少深度/平面约束。
2. 有九组点就一定能准确标定吗？要看模型、分布、参考、匹配、独立检查与实际工况。
3. 三点仿射残差全零说明什么？通常只说明模型精确穿过三组输入，不证明真实测量精度。
4. 为什么裁剪后坐标会整体偏？漏加ROI偏移，或混用了硬件/软件ROI与原图标定。
5. 原图与去畸变图能用同一份像素映射吗？不能默认；其像素空间和成像参数需要匹配。
6. RMS很小能保证每件产品都合格吗？不能，局部极值、覆盖、总误差与判定规则仍未建立。
