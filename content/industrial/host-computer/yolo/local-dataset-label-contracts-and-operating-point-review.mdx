## 1. 把推理框和标注接起来

前面已经完成图片读取、模型推理、原图框、WPF显示和后台会话。本批增加本地离线评价入口：根据显式清单逐张读取可信PNG/JPEG及对应TXT标注，用一次CPU会话顺序推理，输出逐图误检漏检和总体、类别、分组统计。

这次的工具可以接收用户自己的本地图片，但仓库里运行的仍是自有合成样例。没有用户真实标注集，就不能把工具开发完成写成真实质量验收完成，也不能编造准确率。

本轮采用固定分数、NMS和匹配IoU的**单个工作点**。没有阈值扫描、AP/mAP、COCO官方评价兼容声明、训练、模型导出或自动OK/NG判定。

## 2. 类别索引必须和模型一致

当前模型固定为官方YOLOX-Nano及前批SHA256，输出80个COCO类别。标注中的0～79表示模型输出索引，顺序由固定上游类别表确定。它不是COCO标注JSON里可能不连续的category_id，也不是给工业缺陷重新编号后的类别表。

例如0是person，25是umbrella，46是banana；把25重命名为scratch不会让权重具备划痕检测能力。清单固定labelSet=coco80-yolox，模型SHA和pipelineVersion也必须匹配，避免换了一份标签文件就把无关结果解释成产品缺陷。

若将来要评估自训练缺陷模型，需要连同权重、输出契约、类别顺序和预后处理一起增加新的模型适配；本轮不通过任意labelSet绕过固定模型约束。类别名称可对照[固定YOLOX类别表](https://github.com/Megvii-BaseDetection/YOLOX/blob/6ddff4824372906469a7fae2dc3206c7aa4bbaee/yolox/data/datasets/coco_classes.py)。

## 3. 标注五列是什么坐标

每个对象占一行：

```text
class x_center y_center width height
0 0.5 0.5 0.2 0.4
```

后四项都是相对**原图宽高**归一化的数，不是416网络画布，也不是带padding后的坐标。对于100×50图，上面的行表示person框：

```text
x1 = (0.5 - 0.2/2) * 100 = 40
y1 = (0.5 - 0.4/2) * 50  = 15
x2 = 60
y2 = 35
```

本入口只支持普通二维检测框，要求恰好五列，不接收带置信度的预测TXT、分割多边形、旋转框或关键点。类别为整数0～79，数值用InvariantCulture解析；宽高必须大于0，所有数有限且在0～1内，转换后的完整框还必须位于原图边界。

“每项都在0～1”并不保证框在图内，例如中心x=0.01、宽0.2会让左边越界。示例明确拒绝错误标注，不偷偷裁剪真值；边缘浮点舍入造成的越界也应核对标注导出精度。原图连续框右边界可以等于W、下边界等于H，它们不是可访问的整数像素索引。

YOLO五列检测格式可参阅[Ultralytics官方格式说明](https://docs.ultralytics.com/datasets/detect/)。本例只读取这种格式，不据此宣称它能运行所有Ultralytics模型或完整读取其dataset.yaml。

## 4. 空标注和漏标不是同一件事

本例每张图都必须在清单指定一个确实存在的TXT。空文件或纯空白文件表示明确负样本；缺失文件直接失败，不默认当背景。部分工具允许省略负样本标签，本例刻意采用更严格的本地审核规则。

对于所有COCO类别都不含目标的图片，空标注是合理负样本；如果画面里有应该标注的人或车辆却没标，模型检测出来后会被算作FP。评价器并不知道这究竟是模型误检还是人工漏标，所以误检列表必须回看原图和标注。

小目标、遮挡、截断、反光、模糊及不可判样本的处理应在标注规范里约定。本工具没有crowd/ignore、困难样本豁免或局部未标注区域；不能拿部分标注图片直接套用全面评价结论。

## 5. 显式清单与内容指纹

清单记录DatasetVersion、AnnotationVersion、DatasetKind、Partition、模型/标签/处理版本、三类阈值，以及每图Id、Group、路径、尺寸、图片和TXT的SHA256。

| 信息 | 解决什么 | 不能证明什么 |
| --- | --- | --- |
| 图片/标注哈希 | 本次使用了哪份字节 | 标注正确、图片具有代表性 |
| 实际解码尺寸 | 标注对应的栅格边界 | 手机查看器显示方向一致 |
| 模型哈希/标签契约 | 权重与类别索引固定 | 工业缺陷能力或适用质量 |
| PipelineVersion与阈值 | 本轮处理口径 | 代码无需复核、所有平台位级一致 |
| Group | 按工件/批次声明组织复盘 | 真正物理身份、无数据泄漏 |
| validation/test | 本次评价用途声明 | 与训练集内容一定隔离 |

工具每批最多32图、每图128个真值。路径使用清单目录内的相对路径，拒绝父目录跳转、绝对路径和遇到的重解析链接；仅适合可信本地文件，不是对恶意上传或并发篡改文件系统的安全隔离。

标注按实际读取字节核对哈希后形成自有真值快照；图片按解码时读取的同份字节核对哈希和尺寸。清单内不同路径出现相同编码图片哈希也拒绝，防止简单重复图片增加样本权重；重新编码的同一画面可能有不同哈希，仍需按物理分组去重。

本批只评价一份validation或test清单，没有读取训练全集，不能证明训练/验证/测试间无交叉。不要根据test结果反复选择阈值再把同一test分数当最终泛化能力。

## 6. 固定工作点怎样匹配

模型先按分数严格大于scoreThreshold筛选，再执行前批的原图空间、跨类、加1面积NMS。评价时使用可见原图连续框，**匹配IoU不加1**。

在每张图中，预测按分数降序、原始行号升序排列；寻找同类别、尚未匹配的真值中最大连续IoU，IoU大于等于matchIouThreshold才配为TP。真值IoU并列优先较小索引。一个真值只能被匹配一次，剩余预测为FP，未使用的真值为FN。

类别不一致，即使框完全重叠，也会同时留下FP和FN。重复框若已通过NMS仍存在，只有第一个合格匹配为TP。这个贪心口径不是全局最优二分匹配，也不是COCO官方评价器。

原图可见面积为空的保留框单独记为ExcludedPadding，不参与TP/FP匹配；报告仍保留行号、类别、分数和空框信息。这是前批显示裁剪后的评价口径，不能把它忽略掉后直接声称等价于官方框评价。

## 7. 读报告时先看失败案例

总体采用微汇总：先累加所有图片的TP、FP、FN，再算Precision和Recall；不是简单平均各图的比率。类别和Group也分别统计。分母为0时返回null，JSON不会用0伪装一个本来没有定义的比率。

每图保留Truth、所有预测及TP/FP/ExcludedPadding决策、TP对应真值索引和IoU、MissedTruth索引。FP的MatchedIou为空，只表示没有成功匹配，不证明它与所有真值都无交集。

实际复盘建议按漏检目标、错类、低重叠、背景误检分别回看。先排除标注/方向/类别契约问题，再研究采集条件与阈值；对多张相似工件连续拍照，应按Group分组观察，不把每帧都当完全独立证据。

本轮合成样例为两张自有PNG：一张渐变图配任意手写person框，一张黑图配空标签。实际CPU推理得到TP0/FP5/FN1、Precision0/Recall0。这个结果故意不代表真实物体；真值不是从模型输出反推而来，样例只检查导入、推理、匹配和报告闭环。
