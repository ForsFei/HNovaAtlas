## 没有版本控制的日常

你一定见过这样的文件夹：

```text
毕业论文.doc
毕业论文-最终版.doc
毕业论文-最终版-真的最终.doc
毕业论文-改2-新-别删.doc
```

写代码更甚：改好了一个功能，结果把昨天能跑的版本改坏了，想退回去——**退不回去了**。复制粘贴文件当存档，很快就会陷进"命名地狱"，而且无法回答三个致命问题：

1. 这个版本**改了什么**？
2. 这是谁在什么时候改的？
3. 能不能只撤销上周三那次改动？

## Git：给项目装上时光机

**Git** 是版本控制系统（VCS）：给你的项目拍**快照**，每个快照（叫**提交**，commit）永久记录"那一刻所有文件的样子"。

| 游戏存档 | Git |
|----------|-----|
| 打 Boss 前先存档 | 动手改代码前先 commit |
| 读档回到存档点 | 回退到任意一次提交 |
| 多个存档槽 | 分支（第三篇细讲） |
| 云端云存档 | 远程仓库（GitHub，第四篇） |

和手动复制文件夹相比，Git 的快照**只记录变化**：体积小、速度快，并且每次提交都自带"谁、何时、为什么改"的完整履历。

<Callout type="info" title="本站就是活例子">

你现在读的这个网站，它的源码就是用 Git 管理的：每一篇文章的每次修改都有记录，改坏了随时回到任意历史版本，多人协作互不覆盖。学会 Git，你加入的每个项目都用同一套语言协作。

</Callout>

## Git 的三个区域：理解一切的钥匙

初学 Git 的所有困惑，几乎都源于没分清三个区域：

```text
工作区（你在编辑器里改的文件）
   ↓ git add —— 挑出这次想存档的变化
暂存区（打包前的购物车）
   ↓ git commit —— 拍快照
仓库（永久历史）
```

- **工作区**：你眼前的文件，随便改
- **暂存区**：一次提交可以包含多个文件的改动，先 `add` 进"购物车"，攒齐了再一起 `commit`
- **仓库**：`.git` 文件夹里的完整历史，永远不会悄悄丢

为什么要有暂存区？因为你可能同时改了三件事，但希望**分三次提交**（每次提交只含一件事，履历才清晰）。暂存区让你自由挑选"这次提交打包哪些变化"。

## 它远不止是"后悔药"

学会 Git 之后你获得的远不止回退能力：

- **大胆重构**：有存档垫底，敢做大改动
- **看清历史**：任何一行代码是谁为何而写，一查便知
- **团队协作**：多人同时改同一项目而不互相覆盖
- **参与开源**：GitHub 上亿个项目都在等你 clone 下来研究

## 动手试一试

1. 命令行运行 `git --version`，确认 Git 已安装（没有就去 git-scm.com 下载）。
2. 找一个你手头"改名地狱"式的文件夹，想象用 Git 重做一遍会是什么体验。
3. 思考：为什么"每次改完都 commit"比"攒一周 commit 一次"好？（提示：存档点越密，能退回的刻度越细）
