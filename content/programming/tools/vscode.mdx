## 为什么是 VS Code

写 Python 的编辑器选择很多，VS Code 是当前最主流的一个：免费、轻快、微软官方 Python 支持，且**插件生态无敌**。更重要的是它的理念：**编辑器 + 扩展 = 为你的语言定制的开发环境**。

零基础系列默认用它，这篇把它的能力 systematic 过一遍。

## 装机四件套

装完 VS Code，第一件事装这几个扩展（左侧积木图标搜索安装）：

| 扩展 | 作用 |
|------|------|
| Python（微软官方） | 智能补全、语法检查、一键运行、调试 |
| Pylance | Python 语言服务：类型感知的提示与跳转 |
| GitLens | Git 历史 enhanced：每行代码谁何时为何而改 |
| 中文语言包 | 界面中文化（看个人喜好） |

装完 Python 扩展后打开任意 `.py` 文件，右下角选择解释器——**指向你项目的 `.venv`**（虚拟环境篇），补全和检查立刻精准起来。

## 集成终端：告别窗口切换

`Ctrl + ` `（Esc 下方那个键）唤出内置终端。它自动定位在当前项目文件夹，运行 Python、git、pip 全都在这里，不用再开独立命令行窗口。

<Callout type="tip" title="和 Git 面板搭配">

左侧源代码管理图标（分叉线）就是 Git 图形面板：改动列表、暂存、提交、推送全是点按操作。命令行（os-shell 篇）与图形面板**用的是同一个 Git**——图形版适合看状态，命令行适合批量操作，两者混用毫无问题。

</Callout>

## 调试：断点才是理解程序的显微镜

`print` 调试之外，VS Code 提供真正的**断点调试**：

1. 在代码行号左侧单击，出现红点（断点）
2. 按 `F5` 启动调试，程序运行到断点**暂停**
3. 左侧面板查看所有变量的当前值；顶部按钮：继续、单步跳过、单步进入

```python filename="debug-demo.py" {2}
def total(prices):
    result = 0
    for p in prices:
        result += p     # 在这行打断点，看 result 如何一步步累加
    return result

print(total([92, 85, 77]))
```

对着变动的变量看程序一步步走，很多"想不通为什么算错了"瞬间通透。**调试器是理解程序的第一显微镜**，比反复 print 高效得多。

## 效率三件套

| 快捷键 | 作用 |
|--------|------|
| `Ctrl + P` | 按文件名秒开项目里任何文件 |
| `Ctrl + Shift + F` | 全项目搜索文本 |
| `F2` | 重命名变量/函数，所有引用自动更新 |

`F2` 尤其值得养成习惯：改名字永远用重构而不是手动查找替换——它会连注释外所有引用一起安全地改掉。

## 动手试一试

1. 装好 Python + Pylance 扩展，把解释器指向某个项目的 `.venv`，观察补全变化。
2. 给 debug-demo.py 打断点，单步看 `result` 从 0 长到 254 的全过程。
3. 打开源代码管理面板，完成一次完整的 stage → commit → push——你已经能在编辑器里走完 Git 全流程了。
