本课收束这轮五阶段工作。数据库已包含账号、工位和审计，恢复时不能只检查检测列表能否打开；需要把身份、密钥、结构版本和统计一起核对。

## 1. 备份复用一致快照工具

生产运行脚本增加 Backup 模式，继续使用第18课的 SQLite BackupDatabase：

```powershell
pwsh -File F:\TraceReleases\v1\Run-Trace.ps1 `
  -Mode Backup -BackupPath F:\TraceBackups\snapshot-001.db
```

目标必须是新的绝对路径。工具从活动库生成一致快照，检查 quick_check，并拒绝覆盖已有备份。

同一文件包含检测、PGM证据、复核、账号、工位、审计与管理版本。因此恢复不是只复制某张表。Data Protection 密钥在数据库之外，需要按运行簿另行备份并控制访问。

## 2. 升级先在副本上执行

当前存在两个结构版本：索引升级使用 SQLite user_version，管理模块使用 ManagementSchema。它们解决不同的演进问题，不能互相替代。

升级前记录旧版本、发布目录、数据库和密钥位置，在副本上执行显式升级，再检查就绪、登录、查询、复核与统计。未知管理版本会拒绝启动，不能通过直接改小版本号绕过。

如果真实升级还涉及数据转换，应该先增加对应迁移和兼容性检查。本课不会凭空宣称未来所有版本都可向后兼容。

## 3. 回退是切换到已知兼容组合

失败升级副本应保留。准备另一个恢复目录，将已验证快照与原发布版本组合运行，再接入流量。不要在失败文件上反复覆盖和改号，以免失去诊断依据。

恢复到快照会失去快照之后的变更，包括新复核和新账号。实际切换前必须停止写入、核对增量和事件投递；数据库回退不会自动撤回已经被MES接收的外部结果。

账号状态和版本也可能回到过去，导致旧Cookie重新有效。恢复到兼容结构后，在开放流量前执行 `Run-Trace.ps1 -Mode RevokeSessions`，事务性增加全部账号版本并记录审计，要求用户重新登录，不需要重置密码。

## 4. 自动演练的完整路径

在根目录执行：

```powershell
npm run verify:trace -- --deployment
```

`deployment/verify-deployment.mjs` 会真实执行：

1. 发布到新的临时目录，生成生产配置和清单。
2. 显式初始化结构和管理员，导入两条独立证据。
3. 启动发布程序，经过HTTPS本机代理检查页面、就绪、登录及统计。
4. 检查会话Cookie的Secure属性，服务运行中生成快照，验证重复备份被拒绝。
5. 在快照之后新建工位，保留一个明确的增量变化。
6. 将快照恢复到副本，执行索引升级；制造未知管理结构版本，确认程序拒绝启动。
7. 保留失败副本，再从原快照恢复到另一位置，沿用原密钥检查已有Cookie、统计和工位数据。
8. 执行会话撤销，确认旧Cookie被拒绝，原密码仍可重新登录。

恢复后的数据库没有快照之后的工位，原快照的索引版本也没有被副本升级改动。这些检查证明副本隔离和回退结果。

演练使用当前发布程序验证兼容快照，未知版本由故障注入制造；它不是两份真实生产版本之间的升级认证，也不替代目标设备上的长时间运行。

## 5. 完整验收入口扩展

```powershell
npm run verify:trace
```

现在完整入口还包含管理接口、CRLF契约回归、管理浏览器和独立发布演练。可分别运行 `--api`、`--browser`、`--deployment`，定位失败阶段。

浏览器构建依次执行，仍避免共用输出目录的并发覆盖。CI增加部署步骤，失败日志包也会包含实际产生的 deployment.log。

## 6. 远程CI暴露的真实问题

首次远程执行中，内容与接口通过，契约检查却报告生成类型过期。原因是Windows检出可能得到CRLF，而生成器输出LF；原先逐字符比较把换行差异当成契约变化。

修复仅在比较时规范化CRLF，不删除空白、不排序或忽略字段。并发写入检查仍比较原始文件内容，防止覆盖他人修改。

新增测试通过内存读取注入模拟CRLF检出，不改用户文件；已有必需字段漂移测试继续报错如预期。这区分了无语义的换行差异和真正的接口变化。

首次失败运行也实际验证了日志上传：artifact 中包含API与浏览器输出，且任务保持失败状态。配置存在、本机通过、远程通过是三个不同的证据，后续交付记录应分别保留。

## 7. 本阶段交付与后续边界

当前教程已覆盖工位档案、持久化角色、原始NG统计、同范围明细、发布工具与恢复演练。仍然没有绑定真实设备、MES生产环境、组织身份提供商或目标机域名。

后续若继续扩展，优先按实际需求选择组织登录、配方审批或生产批次追溯，并先定义一个完整业务目标。不要因为还有API可加，就无限拆分零散交互。

复习：为什么数据库和密钥必须一起考虑？为什么回退不能通过改小版本号完成？为什么修复CRLF误报后，还要保留真正字段漂移的负向测试？
