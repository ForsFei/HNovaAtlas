前几课处理了复核和下载的失败。操作员日常查列表、打开详情时，也可能遇到请求一直没有完成。这一课给共享 JSON 读取函数设置 15 秒截止时间，失败后允许在原位置重试。

## 1. 重试当前查询

沿用第 3 课的数据库和前端存储模式。打开 [质检列表](http://127.0.0.1:43112/)，选定工位、结果或时间范围，再观察列表读取。 [启动追溯台存储模式](/knowledge/web/full-stack/sqlite-inspection-storage/)

| 情况 | 界面如何处理 |
| --- | --- |
| 列表读取超过 15 秒 | 提示超时，提供「重新加载记录」 |
| 详情读取失败 | 在当前详情显示错误，提供「重新加载详情」 |
| 用户点击重试 | 显示加载状态，重新请求原 URL |
| 用户切换筛选或关闭详情 | 取消旧读取，后续页面只接收自己对应的结果 |

列表重试继续使用当前工位、结果、时间范围和页码。详情重试继续使用当前周期 ID。页面地址保持这些条件，便于操作员确认自己查的是哪一批记录。

实时模式的定期刷新仍在后台读取，已有结果会在新响应返回时更新。用户主动点击重试时，则进入明确的加载状态。

## 2. 把超时和主动取消传给同一次 fetch

`read-json.ts` 创建一个截止控制器，再用 `AbortSignal.any` 将它与调用方的取消信号组合。截止计时器达到 15 秒，或调用方取消请求，都会终止这次读取。函数退出时会清除计时器。 [组合 AbortSignal](https://dom.spec.whatwg.org/#dom-abortsignal-any)

截止时间覆盖等待响应和读取 JSON 响应体。因此，服务器已经发出响应头，但响应体迟迟没有读完，也会结束等待。若已经拿到服务器请求编号，超时提示会带上该编号，方便关联日志。

调用方主动取消通常意味着用户换了筛选或离开详情，旧请求的结果随后会被忽略。截止控制器触发时，用户仍在等当前查询，界面才显示可重试的超时提示。 [React 请求清理](https://react.dev/reference/react/useEffect#fetching-data-with-effects)

## 3. 让每次重试拥有自己的状态

`useJson` 用请求 URL 和重试次数标记当前读取。点击重试只增加次数，筛选 URL 继续沿用。新的读取开始后，旧错误会让位给加载状态，完成后再显示结果或本次错误。

Effect 的清理会取消旧请求。写入状态前也会检查取消信号。这样，切换工位后较慢返回的上一工位响应，就不会显示在新查询下面。

共享读取函数也用于游标续页。续页超时后，游标组件保留已经加载的行和原游标，操作员仍能按「加载更多」重试。后台的首页更新检查失败时，则保留上一次提示。

## 4. 用浏览器验证真正的截止时间

在前端目录运行验收。

```powershell
cd examples/web-quality-trace/lesson-02
npm run test:e2e
```

Edge 会拦住一条已经取到服务器响应的列表请求，让页面持续等待。达到 15 秒后，脚本检查浏览器取消请求、显示超时提示。恢复响应通道后点击重试，验证请求仍携带原工位和结果筛选，页面地址也保持一致。

详情场景会先返回一次带请求编号的 503，确认点击「重新加载详情」后能在同一周期下恢复图片。原有游标分页的取消与重试也会一起验收。

这里的 15 秒是示例对 JSON 读取设置的等待预算。选择生产环境的时间预算时，可以结合第 21 课的请求耗时指标评估。 [请求耗时指标](/knowledge/web/full-stack/request-metrics-and-traffic-drill/)
