上一课提交成功后，待复核列表会重新查询。假设每页一条，原来有两页，操作员在第 2 页完成复核。待办减少到一条后，只剩第 1 页，而地址栏仍保留第 2 页。这一课处理这个边界，让用户能返回有效页码，并继续核对刚保存的详情。

## 1. 根据本次查询的总数判断页码

列表沿用接口返回的 `total`，用每页条数计算总页数。

```typescript
const totalPages = Math.ceil(total / pageSize);
```

| 查询结果 | 页面提供的操作 |
| --- | --- |
| 当前页仍有效 | 显示记录与原来的上一页、下一页 |
| 当前页大于最新总页数 | 提示最新总页数，提供「回到最后一页」 |
| 有多页可选 | 同时提供「回到第 1 页」 |
| 总数为零 | 显示没有符合条件的记录 |
| 总数为零，但 URL 仍指向后面的页 | 提供回到第 1 页的入口 |

页面在用户点击恢复按钮时更新地址。回到第 1 页时会移除 `page` 参数，沿用默认首页。若另一位操作员在恢复请求期间又完成了复核，新响应仍会按同样规则处理。

## 2. 恢复列表时保留当前详情

页码恢复只改变 `page`。工位、结果、复核状态、时间范围和详情 ID 都继续保存在 URL 中。操作员回到有效列表后，仍能看到刚保存的结论、复核人和时间。

列表和详情使用各自的标识维护状态。页码改变会重新读取列表，详情周期 ID 相同则继续保留该详情。点击另一条周期时，才为新的周期建立详情状态。 [React 状态保留与 key](https://react.dev/learn/preserving-and-resetting-state)

普通的上一页、下一页仍按原流程切换列表并关闭详情。恢复按钮用于处理当前页失效时的返回操作。

## 3. 跟做一次末页处理

沿用第 4 课的复核环境，准备同一工位的两条未复核 NG，并选择页码分页。 [启动复核练习](/knowledge/web/full-stack/ng-review-and-authorization/)

1. 进入待复核列表第 2 页，打开记录并提交复核。
2. 列表刷新后，确认页面提示只剩一页，详情仍展示保存结果。
3. 点击「回到最后一页」，确认返回剩余记录，地址保留原周期 ID。
4. 打开剩余记录并完成复核，确认待复核列表显示为空，详情仍可核对。
5. 用保留旧页码的地址重新打开空列表，点击「回到第 1 页」，检查筛选条件与详情仍在。

本例每页一条，便于少量样本触发边界。实际每页显示更多条时，总数和页数使用同样的计算方式。

## 4. 运行浏览器验收

在前端目录执行。

```powershell
cd examples/web-quality-trace/lesson-02
npm run test:e2e
```

Edge 会用独立工位的两条待办完成上述流程，检查最后一页处理后的总页数、恢复后的 URL、筛选和详情。它还会完成最后一条待办，再验证空列表和旧页码的恢复入口。
