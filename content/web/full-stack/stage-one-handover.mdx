前五十课已经串起查询、证据下载、NG 复核、实时更新、失败恢复和自动验收。本课建立一个阶段交付点，先确认别人能按说明运行，再进入工位配置、持久化账号、统计和部署。

## 1. 从一份运行说明开始

仓库中的 `examples/web-quality-trace/README.md` 集中记录环境、安装、启动方式、验收和代码演进目录。知识库用 43110；示例 API 用 43111，Vite 页面用 43112。不要把三个服务的端口混在一起。

当前验收环境是 Windows、Node.js 24、.NET 10 SDK 和 Microsoft Edge。前端有独立锁文件，仓库与前端的依赖都需要安装。

```powershell
npm ci
npm ci --prefix examples/web-quality-trace/lesson-02
npm run verify:trace
```

完整入口生成模拟工位证据，导入临时数据库，执行接口、数据库、契约与浏览器场景。它不需要连接真实 PLC、相机或 MES。

## 2. 理解代码目录

`lesson-01` 是内存 API，`lesson-02` 是持续演进的 React 页面，`lesson-03` 是当前 SQLite API。课程编号与目录编号不是一一对应关系。后面的文章继续修改同一项目，不需要为每一课复制整个应用。

## 3. 区分本机结果和远程结果

本机完整验收通过说明当前工作目录能通过检查；推送后的 Actions 结果说明仓库提交在 runner 上的表现。二者都需要记录对应的代码版本。

失败时先看最后一个 `[trace]` 阶段。`--api` 和 `--browser` 可分别复现。浏览器日志中的临时目录属于执行那次检查的机器，不能把 runner 路径当作本机路径。

## 4. 后续按业务阶段推进

| 阶段 | 新增能力 | 验收重点 |
| --- | --- | --- |
| 工位配置 | 工位创建、编辑、停用、并发保护 | 重复编码拒绝、输入错误、旧版本冲突 |
| 用户权限 | 密码哈希、持久化账号、角色、停用 | 服务端授权与旧会话失效 |
| 统计 | 时间范围、工位、NG 和待复核统计 | 分母、边界、明细与汇总一致 |
| 部署 | 独立发布、HTTPS 入口、数据与程序分离 | 备份恢复和升级失败回退 |

每阶段以业务闭环划分课程。不会把一次变量移动或很小的样式调整都拆成一课。

## 5. 当前交付边界

演示账号来自环境变量，仍属于本地练习模型；数据库升级和恢复已有演练，尚需在后续阶段形成独立部署运行簿。离线追溯不等于设备控制系统，新增后台配置也不会直接驱动设备。

跟做时先按 README 启动，再解释每条依赖和端口的用途。只有能从干净检出重现结果，阶段交付才有可复查的基础。
