上一课在独立内存库里验证了候选索引。应用已经有自己的 SQLite 文件，数据库升级需要能识别当前版本、重复执行，并在失败时保留可核对的状态。这一课把候选索引应用到已有库的副本。

## 1. 从备份副本开始

先确认实际使用的追溯数据库。如果之前传过 `--TraceDb`，把下面的源路径换成实际位置。

```powershell
$source = (Resolve-Path 'examples/web-quality-trace/lesson-03/.local/trace.db').Path
$copy = Join-Path $env:TEMP ("atlas-upgrade-" + [guid]::NewGuid().ToString("N") + ".db")
dotnet run --project examples/web-quality-trace/lesson-03 -- --TraceDb $source --Backup $copy
dotnet run --project examples/web-quality-trace/lesson-03 -- --TraceDb $copy --Migrate true
```

第一次成功会打印 `Trace database upgraded to version 1`。再运行同一条迁移命令，会打印已经处于版本 1。

迁移命令打开已有文件，完成后退出。应用普通启动仍使用当前库提供查询，执行升级需要显式调用迁移入口。需要备份时使用单独的命令。

## 2. 在事务内完成索引与版本更新

本课用 SQLite 的 `PRAGMA user_version` 记录教学数据库的结构版本。旧库从 0 开始，版本 1 表示已应用第 22 课验证过的索引。

```sql
CREATE INDEX IX_Inspections_Station_Result_ImportedTicks_Id
    ON Inspections (Station, Result, ImportedTicks, Id);
PRAGMA user_version = 1;
```

迁移先建立写事务，再读取版本。建索引和写版本在同一个事务里提交。如果其中一步失败，事务释放时会回滚。这样后续运行可以根据提交后的版本判断是否还需要升级。 [SQLite user_version](https://sqlite.org/pragma.html#pragma_user_version) · [Microsoft.Data.Sqlite 事务](https://learn.microsoft.com/dotnet/standard/data/sqlite/transactions)

## 3. 重复执行和冲突怎么处理

| 当前情况 | 命令行为 |
| --- | --- |
| 版本 0，索引可以创建 | 创建索引并提交版本 1 |
| 版本 1 | 报告已应用 |
| 版本 0，存在同名索引 | 报错并保留版本 0，便于核对索引定义 |
| 其他版本 | 报错并保留原版本 |

使用非延迟事务，两个升级进程竞争同一文件时，写入由 SQLite 串行处理。后取得事务的进程会读取前一个进程提交后的版本。如果写锁持续占用，命令仍可能超时。安排升级时可先停止对目标库的写入。

同名索引冲突需要先检查数据库版本和实际列顺序。同名并不能保证索引结构一致，本例让这类差异显式报错。

## 4. 用新版本副本启动 API

```powershell
dotnet run --project examples/web-quality-trace/lesson-03 -- --TraceDb $copy --urls http://127.0.0.1:43116
```

打开 [升级副本的检测列表](http://127.0.0.1:43116/api/inspections?station=station-a&result=NG)，确认同样的筛选仍能返回原有记录。再检查 `/health/ready`。

应用模型的基础建库与已有库升级是两个入口。教学升级目前只有 0 到 1 这一步，通过 SQLite 事务管理。回退演练可按第 18 课从升级前快照另建副本，先确认恢复结果，再决定使用哪一份数据库。

## 5. 验证升级和失败路径

```powershell
dotnet build examples/web-quality-trace/lesson-03
node examples/web-quality-trace/lesson-03/verify.mjs --migrate
```

脚本从同一个旧库创建两份测试副本。一份验证并发升级、索引列顺序、版本和记录一致，并启动 API 查 NG。另一份故意创建同名异构索引，检查失败时版本保留为 0。它也验证不支持的版本会被拒绝。

复习时试着解释，为什么版本检查要放在事务内，以及为何确认索引存在之后还要验证旧查询的业务结果。
