# Phase 9：主题、响应式与性能

## 已实现与取舍

- 深色 / 浅色 / 跟随系统沿用 `next-themes` + `data-theme` 与 `src/styles/tokens.css` 语义 Token；主题选择保存在浏览器端，不额外请求服务器。系统偏好变化由既有主题库处理。未为单一组件硬编码主题颜色。
- 手机导航使用原生 `details`，摘要名称固定为“主导航菜单”，展开状态由原生语义表达；键盘 Esc 与跨页关闭沿用现有逻辑。布局按容器收缩，代码和图表允许局部横向滚动，不使整页横向溢出；减少动画偏好关闭平滑滚动和过渡。
- 长文章 TOC 仍以 `requestAnimationFrame` 合并滚动更新，但只对可见的桌面/移动目录计算位置；缓存标题元素，并以二分查找选择阈值之前的最后一节。10,000 标题的纯函数测试最多读取约 15 个位置，而非顺序读取 10,000 个。正文动态增高时仍读取当下位置，不缓存过期的像素坐标。
- 知识浏览页与技术侧栏是密集的文章链接，不对进入视口的每个链接预取完整静态文章，也不在悬停时预取；点击仍使用 Next.js `Link` 客户端导航。少量的上一篇/下一篇与首页入口保留默认预取，权衡点击延迟和无意网络请求。
- 搜索弹窗在打开时、Pagefind 在输入后、Mermaid 图表在接近视口后才加载；本阶段未把大型库移入全局入口，也未新增依赖。

## 验证与边界

Phase 8 导出的基线首页与知识浏览页各有 8 个 HTML 直接引用脚本，原始文件大小合计约 596 KB；这是未压缩的静态引用大小，不是实际传输量，也不应当解读为本轮减少了约 596 KB。Phase 9 着重减少滚动时布局读取与大规模目录可能产生的背景请求，不声称已完成网络或 Core Web Vitals 的实测提速。

已通过 `npm run lint`、`npm run typecheck`、`npm run test:content`（40 项）与 `npm run build`。生产浏览器已检查深色/浅色/跟随系统、320/375/768/1024/1440px、手机目录与导航、桌面当前章节、搜索和交互文章。静态导出与 Pagefind 发布索引仍只包含六篇已发布文章。

当前有八篇发布内容。10,000 标题测试只验证 TOC 查找复杂度，不代表已证明 10,000 篇文章的静态构建时间、文件大小或 Pagefind 索引性能；真正扩容前需使用代表性内容进行构建与浏览器压测。无自有域名，不设任意 canonical URL、Sitemap 或 robots 发布策略。
