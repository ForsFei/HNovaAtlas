# WPF 学习路线与分步交付计划

更新：2026-10-16。目标是在 HNova Atlas 建立一条能用于基础复习、项目实践和面试追问的 WPF 主线。承接站内 C#，但不把 C# 语法再写一遍，也不靠大量网页互动代替真实桌面程序。

## 内容原则

- 每步围绕可观察的问题组织：概念与运行规则 → 最小示例 → 常见误区 → 自测。优先用官方文档核对，正文原创整理。
- 已有 `/knowledge/desktop/wpf/architecture/mvvm/` 保留 URL；后续扩充或从新文章回链，不迁移已有书签。
- 示例以 .NET 10、`net10.0-windows` 为基线；可在本机 Windows 编译。需要真实界面的行为只在可运行 WPF 示例中验证，不假装站点静态构建能证明视觉或 Dispatcher 行为。
- 默认不引入 MVVM 框架或额外 NuGet 包。需要时先讲 WPF 原生机制，再说明库解决了哪类重复工作。
- 阶段划分是交付节奏，不把基础、进阶和面试拆成三套课程；实际内容可按学习反馈调整。

## 分阶段路线

| 步骤 | 核心问题与范围 | 交付与验收 |
| --- | --- | --- |
| 1. 应用与布局 | WPF 与 C#/.NET 的关系；`App`、`Window`、XAML/code-behind；测量/排列、`Grid` 的 `Auto/*` 和 `StackPanel` 的适用边界 | 总览页、布局入门、最小 WPF 程序；编译成功，窗口缩放时主要区域不会依赖硬编码坐标 |
| 2. 绑定与通知 | `DataContext` 继承、绑定源/目标、`OneWay`/`TwoWay`、`INotifyPropertyChanged`、集合增删与项属性变化 | 深化原 MVVM 页及可运行 ViewModel/集合示例；分别验证三类变化，不把绑定失败误当业务值错误 |
| 3. 命令与输入验证 | `ICommand`、`CanExecute`、按钮状态、转换/验证错误与用户反馈 | 一个设备参数编辑流；验证有效/无效输入、命令启用与取消/重复提交边界 |
| 4. WPF 属性与外观 | 依赖属性、附加属性、路由事件；资源查找、样式、控件模板与数据模板 | 解释值来源与模板边界；最小对照示例区分“改样式”和“改控件结构” |
| 5. UI 线程与异步 | Dispatcher 亲和、`async/await`、取消、窗口关闭后的回调、错误归属 | 可控慢操作示例；界面持续响应，取消与关闭路径无跨线程更新或遗留任务 |
| 6. 列表与性能 | `ItemsControl`/`ListView`、集合视图、筛选、虚拟化条件和绑定诊断 | 大列表的可观察对照；说明虚拟化何时失效，避免没有测量就宣称性能提升 |
| 7. 小型整合与测试 | 将前面机制组合成简单设备读数面板；ViewModel 单元测试与 WPF 集成边界，发布注意事项 | 不接真实硬件的本地示例、测试和运维/发布清单；不把示例包装成完整工业控制系统 |

每步只新增当前需要的文章/代码，并在完成后运行站点内容扫描、测试、lint、类型检查和静态构建；WPF 示例另做独立编译。阶段结束时更新本计划的实际完成情况。若用户指定更优先的 WPF 痛点，可改变后续顺序。
