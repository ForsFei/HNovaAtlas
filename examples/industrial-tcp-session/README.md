# TCP 长连接、心跳、恢复与 WPF

.NET 10，无第三方包。仅链接前两节的 WireProtocol 与纯 CRLF 解析器。
所有演示/检查都绑定 `127.0.0.1` 系统分配端口，不接触现场设备。

从仓库根目录执行：

```powershell
dotnet run --project examples/industrial-tcp-session/Checks/TcpSession.Checks.csproj
dotnet run --project examples/industrial-tcp-session/Wpf/TcpSession.Wpf.csproj
```

第二项仅 Windows WPF。选择场景后启动；窗口会启动一个本机 TCP 模拟器，
复用连接，按顺序 PING → READ TEMP → 等待一秒 → 重复。
点击停止或关闭窗口后，先取消并等待监控退出，再停止并等待模拟器。

## 协议

沿用上一节 `READ <32位请求号> TEMP\r\n` / `TEMP <同一请求号> 253\r\n`。
新增 `PING <请求号>\r\n` / `PONG <同一请求号>\r\n`。
ASCII，载荷最多 96 字节；一个连接持续使用同一个解析器。
PONG 只表示应用协议通路有响应，不等于设备安全、运动完成或温度采样更新。

## 对象边界

- `TcpConnection`：一个持续接收任务，最多一个在途请求。发送门串行化调用，
  先注册 TaskCompletionSource 再写入，按编号和类型匹配。旧/重复响应忽略并计数。
- `TcpMonitor`：连接、健康周期、有限恢复和不可变最新快照。WPF 每 200 ms 在 UI 线程取快照，
  不把控件引用传给网络层，不逐字节排 UI 更新；历史最多 100 条，值超过三秒标过期。
- `LoopbackDevice`：单连接顺序教学设备，真实本机 socket。其 LastSessionError 记录已观察的会话错误。
- `Checks`：验证长连接复用、请求关联、恢复、空闲 EOF、心跳/采样超时及取消。

连接期限 2 秒；每个请求发送与等待总期限 1 秒（排队等发送门不计入该期限）。
心跳和温度查询按顺序执行，不使用并发定时器。每个完整周期之后延时一秒，因此不是严格一秒采样。
收到 EOF、I/O 失败或超时后先取消/释放旧 socket，await 接收任务，再开始恢复等待。
恢复等待默认 250 / 500 / 1000 ms，连续第 4 次失败进入 Faulted；通用延时上限为 2000 ms。
只有完整的 PONG + 温度响应成功才清连续失败计数，不在 Connect 成功时清零。
协议格式/类型失败直接 Faulted，不自动重连。

自动恢复只重建读取会话并发出新的只读请求，不重放旧请求或动作。
新会话使用新解析器、待响应对象与请求号；失败/停止清温度及采样时间。
数据龄使用 Stopwatch 单调时钟，不以墙钟修改来判断新鲜度。

## 故障场景

| 模式 | 行为 |
| --- | --- |
| Normal | 同连接持续心跳与采样 |
| DropOnce | 第一次采样成功后，在下一个心跳时断开；第二次连接恢复正常 |
| IdleCloseOnce | 第一次采样后空闲 100 ms 再关闭，验证无需等下一轮请求才发现 EOF |
| PartialOnce | 第一条连接只回半个 PONG 就关闭；新连接正常，不能继承旧半帧 |
| SilentPing | 不回心跳，达到失败上限后停止 |
| SilentTemperature | 回心跳但不回温度，仍应达到失败上限 |
| StaleReplies | 每个正确响应前先发一个旧编号 |
| DuplicateReplies | 每个响应发送两次 |
| Malformed | 响应为 BROKEN，协议失败直接停止 |
| WrongKind | 编号正确但响应类型错误，直接停止 |

界面显示最新状态，不是完整审计日志；快于 200 ms 的中间状态可能被合并。
故障注入是应用级教学行为，不是网络丢包、工业实时性或驱动认证测试。

## 验收边界

检查使用真实回环网络，但不是现场硬件验收。WPF 编译与 Core 自动检查分开记录，
不能据此声称已人工操作窗口、检查所有屏幕尺寸或验证关窗的视觉效果。
生产场景还需按协议选择心跳与恢复策略、多实例退避抖动、TLS/认证、设备操作权限、
状态审计和动作幂等/握手。这里没有实现并发请求表、自动设备复位或动作恢复。
